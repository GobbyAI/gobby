# Codewiki Model-Tier Narrative Bakeoff (2026-07)

Three-arm comparison of codewiki **aggregate narrative** quality by model tier
(#17531, under epic #17713). The deliverable is the narrative/aggregate pages —
`code/narrative/**`, `code/repo.md`, `code/_architecture.md`, `code/concepts/**`
— generated by three candidates over the *same* frozen source snapshot with the
*same* file/module substrate.

| Arm | Output dir (wiki-bakeoff/outputs/gobby-2026-07) | Aggregate candidate | Route |
| --- | --- | --- | --- |
| S | `arm-sonnet` | `claude/sonnet@xhigh` (explicit pin) | daemon |
| O | `arm-opus` | `claude/opus@xhigh` (explicit pin) | daemon |
| G | `arm-default` | *(none — default `feature_high` profile → `codex/gpt-5.5@xhigh`)* | daemon |

Raw artifacts (wikis, run logs, divergence lists, judging JSONL) stay under
`~/Projects/wiki-bakeoff/outputs/gobby-2026-07/` (preserved, never committed).

## Methodology

- **Frozen snapshot.** Arms O and G ran with
  `--project /Users/josh/Projects/wiki-bakeoff/gobby-frozen-2b2bc1848`, a git
  worktree pinned at `2b2bc1848` (the 0.5.0 branch state before arm S's final
  publish). Codewiki reuse keys on content hashes of
  `project_root.join(relative_path)`, so the frozen checkout makes file/module
  pages reusable across arms while aggregate pages regenerate per candidate.
- **Arm lineage.** S was generated first (live repo, 12 attempts across several
  days). O seeded from S's published vault; G seeded from O's healed published
  vault. Per the #17530 reuse-invalidation contract (live-validated 2026-07-02),
  aggregate-writer pages regenerate when the requested `--ai-aggregate-candidate`
  differs from the recorded one; file/module pages reuse by content hash.
- **Defaults untouched.** `ai.generation.profile_defaults` has **no DB
  overrides** (verified via `list_config_keys` at judging time); arm G exercised
  the stock `feature_high` profile.
- **Blind judging.** Chapters `01-overview`, `04-workflows`,
  `09-troubleshooting`; pairs S–O, S–G, O–G; judges `claude/opus` and
  `codex/gpt-5.5` via the daemon chat route. Frontmatter stripped, X/Y label
  assignment randomized per call (seed 17531) and recorded for unblinding.
  Raw verdicts: `outputs/gobby-2026-07/judging-results.jsonl`.

All 18 blinded calls completed with zero errors, and the two judges agreed on
the winner in **all nine** comparisons (perfect inter-judge agreement).

| --- | --- | --- | --- |
| `01-overview` | **S** (both judges) | **S** (both) | **O** (both) |
| `04-workflows` | **S** (both) | **S** (both) | **O** (both) |
| `09-troubleshooting` | **O** (both) | **G** (both) | **O** (both) |

Aggregate wins across the 18 verdicts: **S 8, O 8, G 2**. Head-to-head:
S beats O 2–1 chapters, S beats G 2–1, O beats G 3–0.

Recurring rationale themes (verbatim excerpts in
`outputs/gobby-2026-07/judging-results.jsonl`):

- Judges consistently rewarded **specific, verifiable anchors** (exact
  `file:line` ranges, real symbol names, concrete datastores) and punished
  broad or mismatched citation ranges.
- Opus's `01-overview` loss to sonnet came down to citation quality: sonnet
  cited "exact contract JSON line ranges, concrete asset examples … the actual
  re-exported symbols", while opus leaned on the declarative contract with
  "broad, vague ranges (e.g. … lines 67-1938)".
- Opus swept `09-troubleshooting` and every O–G pair for grounding claims "in
  the actual Rust source … with narrow, specific line ranges" and describing
  "the real runtime path".
- gpt-5.5's chapters were the longest but judged less internally consistent
  ("mixes packaging with runtime troubleshooting … anchors behavior to weak or
  mismatched ranges").

## Gate: file/module substrate identity

Primary invariant: O and G must share the file-page substrate byte-for-byte so
the comparison isolates aggregate authorship.

- **O vs G:** 31 of ~2,900 file pages differ
  (`outputs/gobby-2026-07/o-vs-g-files-divergence.txt`). All 31 are live-index
  drift regenerations: graph-neighborhood fingerprints come from the *live*
  index, which other sessions kept advancing between O's run (05:01–06:40 CDT)
  and G's run (06:55–09:02 CDT); several of the 31 are files deleted or edited
  in the live repo after the frozen SHA. Both arms regenerate such pages with
  the same file-tier models, so this drift does not touch aggregate authorship.
- **S vs O:** 456 divergence lines
  (`outputs/gobby-2026-07/s-vs-o-files-divergence.txt`) — expected and
  disclosed: S was built across a drifting HEAD over several days; O rebuilt
  the drifted set at the frozen SHA. S's substrate is therefore *not*
  hash-identical to O/G; S's aggregate comparison stands on the narrative pages
  themselves.

## Disclosure ledger

The bakeoff took 12 attempts for arm S, 12 for arm O, and 1 for arm G, because
it kept colliding with real codewiki/daemon defects. Every defect became a
task; six were fixed *during* the bakeoff with the fixes live-validated by the
arms themselves.

**Bugs found and fixed (tasks):**
- #17823 — publish link validation flagged wikilinks inside code spans.
- #17848 — narrative plan normalization: canonical spine titles pinned so tour
  links resolve after model-authored merges.
- #18005, #18109 — index-lags-disk crashes on deleted sources (hash-snapshot
  skip pattern).
- #18190 — `_ownership.md` keyed on emitted module-link set so cluster renames
  invalidate stale pages.
- #18248 — `PublicationFingerprint::from_run` crashed on sources missing from
  disk (frozen checkouts predate additions).
- #18285 — tool_chat bounded a full multi-turn agentic run with the 60 s
  single-generation spawn-cold budget; every opus aggregate died at 60 s.
  Fixed: candidates bound by the overall attempt budget (1200 s).
- #18288 — same mis-budgeting on the plain generate route (narrative/concepts):
  route now caps caller-supplied per-candidate timeouts at the total budget
  only, and gcore sends LongForm (=total) budgets for Aggregate-tier
  generations on both pinned and profile paths.
- #18291 (open) — reuse preserves a degraded `_ownership.md`: reuse keys ignore
  the degraded flag, so heals never regenerate it.

**Design flaw (open, #18252):** `stage_is_compatible` demands exact
`PublicationFingerprint` equality; any drift (including the *live* index's
`index_snapshot_hash`, even with frozen sources) discards the whole stage and
re-pays the sweep. This forced full re-sweeps on attempts 10, 11, 12 and arm G.
Redesign (per Josh): publish-then-converge — on drift, run fail-closed link
validation on the staged vault, publish if valid, re-seed from the updated
vault; discard only on validation failure. Implementation in progress in a
separate session.

## Verdict

On these three chapters, with two independent judges in perfect agreement:

1. **Claude tiers beat the gpt-5.5 default decisively for narrative
   aggregates.** Opus swept gpt-5.5 6–0; sonnet beat it 4–2. The stock
   `feature_high` profile (gpt-5.5@xhigh) produced the longest chapters but the
   weakest citation discipline.
2. **Sonnet@xhigh holds its own against opus@xhigh** (4–2 on verdicts, 2–1 on
   chapters), winning on citation specificity in overview/workflows; opus won
   troubleshooting on runtime grounding and was the only candidate whose plan
   added a chapter (`10-build-packaging`). Given opus's cost and latency
   (~minutes/page vs sonnet's ~1 min/page), **sonnet remains the sensible
   default aggregate candidate**, with opus a defensible upgrade for
   troubleshooting/architecture-heavy surfaces.

Caveats: single run per arm; three chapters judged; arm S's substrate was
built across a drifting HEAD with more heal passes than O/G (both single-pass
over the frozen snapshot); judges were the same two model families as the
contestants (mitigated by blinding and their unanimous cross-family
agreement).
