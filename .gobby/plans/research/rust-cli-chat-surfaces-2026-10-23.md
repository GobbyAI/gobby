## Research Findings

### Research Questions

- Which open-source Rust projects give existing coding CLIs chat input/output and structured approvals or decisions?
- Which support Claude Code, Codex, AGY, Droid, and Grok, and which are reusable crates versus applications?
- What do licensing, activity, and releases imply for choosing a base?

### Domain Context

**Recommendation: ACP Rust SDK for a new Rust product; Codync for an existing chat-and-approval application; BitRouter for reusable terminal presentation; Pandemonium for a native Rust GUI.** Rankings are research judgments, not runtime test results.

Snapshot: 2026-10-23 UTC. Public web and upstream source research only; no project was installed or exercised against live agents. Stars and commit/release metadata came directly from GitHub's public API. Dates below are UTC. Last commit means the default-branch `/commits?per_page=1` result, not `pushed_at`, which can include other branches. Stars indicate attention, not correctness.

AGY is interpreted as Google Antigravity; Grok means xAI's Grok Build CLI. The official ACP registry now includes [Antigravity](https://github.com/agentclientprotocol/registry/blob/main/antigravity-acp/agent.json), [Factory Droid](https://github.com/agentclientprotocol/registry/blob/main/factory-droid/agent.json), and [Grok Build](https://github.com/agentclientprotocol/registry/blob/main/grok-build/agent.json). Launch paths are respectively `agy_acp_server`, `droid exec --output-format acp-daemon`, and `grok agent stdio`. Those three agent entries are proprietary: the open-source frontend and the agent runtime have separate licenses.

ACP offers structured chat/tool updates and `session/request_permission`: tool-call information plus labeled options with stable IDs and allow/reject scopes. Clients can draw controls and return a selection or cancellation. [ACP tool calls](https://agentclientprotocol.com/protocol/v1/tool-calls). General decisions are separate: `elicitation/create` supports schema forms and enum choices with accept/decline/cancel, conditional on advertised capabilities. Permission support alone does not establish arbitrary question buttons or native plan-menu parity. [ACP elicitation](https://agentclientprotocol.com/protocol/v1/elicitation).

**Nothing was verified as an entirely Rust, ready-to-embed chat widget with five live-tested CLI integrations and general decision buttons.** Codync is the closest complete application, with a Rust host and mixed-language clients. Registry support offers a plausible all-five route, not a five-agent integration test. Terminal hosts preserve native interfaces without providing a common structured chat/decision model.

Excluded as requested: agentapi, Happy, Omnara, claudecodeui, Vibe Kanban, Telegram bridges.

### Risks

- **Coverage:** registry installation establishes an ACP route, not feature parity or live validation. Codync is the closest documented all-five route; each adapter/client pair still needs capability checks. [Registry](https://github.com/agentclientprotocol/registry), [Codync architecture](https://github.com/leepokai/Codync/blob/main/README.md#how-it-works).
- **Hidden scraping:** outward ACP can conceal screen-derived upstream approval semantics, as in claude-code-cli-acp. [Recognizer](https://github.com/moabualruz/claude-code-cli-acp/blob/main/src/terminal/recognizers.rs).
- **Decision scope:** permission choices, general forms, native plan menus, and workflow gates are distinct. Pandemonium's reviewed model explicitly supports general choices/forms; this is source evidence, not an end-to-end UI test. [Model](https://github.com/JoakimCarlsson/pandemonium/blob/main/crates/pm-acp/src/elicitation.rs), [protocol](https://agentclientprotocol.com/protocol/v1/elicitation).
- **Reuse:** Rust hosts may depend on non-Rust agent bridges or UIs. Zed application licensing differs from GPUI. Library boundaries are clearest in the SDK and BitRouter; Pandemonium is extractable source with internal dependencies. See linked manifests above.
- **Evidence limits:** cached docs lagged current main in material places. Current raw source and GitHub API resolved the noted adapter/version differences. No agent runtime or frontend was executed; no credentials, bootstrap files, processes, daemon state, or source code were touched. Only this artifact is intended for commit.

**Ranked recommendation**

1. **ACP Rust SDK** for Josh's own Rust chat/decision product: existing protocol foundation, custom UI, explicit capability negotiation.
2. **Codync** for adapting a complete chat/approval application: closest functional match and broad registry coverage; mixed-language clients.
3. **BitRouter `bitrouter-tui`** for an embeddable terminal surface: explicit library boundary and structured permission controls; inspect/pin the alpha version.
4. **Pandemonium** for a native Rust GUI and richer forms: permissive layered source, substantial early-project risk.
5. **tty7** for preserving all five native CLI interfaces: broad documented coverage; common chat and structured decision controls still need building.
