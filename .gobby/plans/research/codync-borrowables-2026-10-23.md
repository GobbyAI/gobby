### Evidence & Sources

**Contract mapping shared by all UI candidates**

- Compose `web/src/components/ui/` primitives: existing Button variants, DropdownCaret, SegmentedControl and Select/NativeSelect split. Preserve the composer-only button exception. Evolve `web/` in place.
- Use shipped hue-125 brand accent and tinted neutrals; info 250 for thinking, warning 75 for approval, destructive 350 for failures; success uses lightness and icon. State needs text/icon/position as well as hue. Codync's avatar swatches and red error palette (`apps/desktop/src/renderer/lib/theme.ts:74–105`) are unsuitable imports. Gobby prohibits agent-specific accent colors.
- Use Geist Sans, JetBrains Mono for code/values, fixed rem scale and 65–75ch prose. Preserve density without hiding consequential decision details. Do not import Codync's typography, custom controls or avatar animation system.
- WCAG 2.2 AA, accent focus rings, keyboard parity, both themes, grayscale-readable state, reduced motion and 44px touch hit areas through expansion. Mobile layout is width ≤767px **or** height ≤500px; pointer type controls target size only. Mono content wraps on mobile; nested horizontal card scrolling is prohibited.

**Existing Gobby mechanisms and a correctness concern**

- `web/src/components/chat/ToolCallCardInteractions.tsx:23–135` already supplies approvals and disconnection feedback. Static inspection found its inactive branch derives “Approved” from `call.status === "completed"` and “Rejected” from `"error"`. Verify the upstream contract: execution failure must not become evidence of a denied permission. This concrete concern goes to the Orchestrator; source edits are outside this research seat's role.
- `web/src/components/chat/CommandPalette.tsx:36–421` already implements a palette; `SessionItem:423–474` shows ref/title/time. `AgentStatusBar.tsx:77–258` already formats session state. Improve these existing surfaces before adding navigation/status systems.
- `web/src/components/chat/CompactionSummaryCard.tsx:6–19` already marks transcript compaction. The proposed addition is inspectable provenance/context. The component uses supplied content as its separator label; this research did not verify whether all producers supply a short label or a full summary.

**Secondary engineering patterns**

- **ACP response progress during replay.** `host/src/agent/acp.rs:187–190,208–242` documents a deadlock scenario: `session/load` emits history notifications before its response; a reader blocked on a full notification queue cannot reach that response. Borrow separation of response resolution from notification consumption as a provider-transport review/test scenario. Other useful details: additive update variants kept as JSON (`1–3`), typed failures (`75–107`), 12-line stderr tail (`18–19,193–205`), and pending waiters failed on EOF (`239–242`). Do not literally copy the unbounded queue: define memory/payload limits, spooling or overload behavior, cancellation and redaction. Exclude shell launch/inherited authority (`165–183`) and substring authentication detection (`59–66`). **Target:** backend behind web/gclient/Pro; present failures through existing status UI/tokens. No Gobby ACP defect or need to replace its provider abstraction was established.
- **Separate connector storage, public projection and agent transport projection.** `host/src/market/mod.rs:60–128` distinguishes command/remote connectors, omits OAuth connectors awaiting sign-in from ACP launch, exposes key names/auth state instead of values, and strips URL userinfo/query/fragment. Borrow “configured / needs sign-in / ready” presentation and deliberate secret-free DTOs. **Target:** web integration settings/installer, Pro scoped by host, canonical fields and icon/text state. Reuse Gobby's MCP proxy and registry. The public projection still exposes a command string: arbitrary custom commands, arguments, errors and logs require their own redaction review. Exclude the update/install policy and transport defects below.

### Risks

- **Required exclusions:** the prior `.gobby/plans/research/codync-security-audit-2026-10-23.md` at this same source commit remains the baseline. Do not copy **F1** plaintext API-token database storage without enforced private directory/database/WAL/SHM permissions; **F2** default auto-approval with no added OS sandbox; **F3** mutable ACP acquisition or silent registry/connector executable upgrades; **F4** default-on telemetry or automatic linkage of earlier activity to an account; **F5** prefix-based loopback exceptions or authenticated legacy-SSE forwarding to server-selected origins. Approval cards do not provide OS isolation. Application update settings do not freeze registry-driven executable changes.
- Also exclude integrations enabled across bots by default, cloud registration without deliberate choice, detailed public health, insecure identity-storage fallback, imported branding and assumed hosted-cloud entitlement. Audit F6–F7 and its installation/network sections document the additional concerns. The audit's primary-account installation hold stands.
- Runtime appearance, computed contrast, focus behavior, reduced motion, responsive geometry and asynchronous failure/races remain unverified. Future UI acceptance needs both themes, grayscale, keyboard, coarse-pointer hit targets and 440×956, 932×430, 1440×900 views. No Codync WCAG pass is claimed.
- The Orchestrator should assign verification of the approval-status correctness concern and fix it if execution errors are mislabeled as rejection. Other candidates are proposals; this researcher created no implementation tasks and makes no blanket claim that existing Gobby equivalents are absent.
- **Ranked recommendation:** **1)** enrich existing approval cards with operation/location/scope and authoritative decision outcomes; **2)** add activity/attention previews and jump-to-pending-decision summaries through existing session navigation; **3)** refine activity disclosure and delivery recovery within existing chat; **4)** expose handoff context before considering editable lifecycle controls; **5)** apply host hierarchy/recovery and connector readiness when Pro/installer need them. Review ACP replay handling as a focused engineering scenario. Follow-up remains below #24797 and 1.0 work; a wholesale Codync UI import is unwarranted.
