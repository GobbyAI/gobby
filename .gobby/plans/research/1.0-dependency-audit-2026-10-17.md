## (c) What a node still needs Python or Docker for once the hub-node path closes

Verified Python-free: gdaemon in node mode builds no native runtime and no Python backend supervisor
(`crates/gdaemon/src/state.rs::RuntimeState::prepare` refuses node mode; `crates/gdaemon/src/serve.rs`
line 135 skips the runtime and pool), and it holds no datastore. Hooks go through ghook to the local
node (#24150), spawns run in node gdaemon (#24148), and MCP stdio is gmcp (#24355). Remaining gaps:

1. **Install needs Python plus Docker or the hub DSN.** `gobby install` is Python
   (`src/gobby/cli/install.py`). `src/gobby/cli/_install_daemon.py` lines 95-110 require either a
   running Docker daemon ("Docker daemon is required for full install") or remote datastore mode with
   the hub `database_url` in the node's bootstrap, which conflicts with ROADMAP decision 17 (a node
   holds no datastore credentials).
2. **Enrollment needs Python.** `gobby auth login` exists only in `src/gobby/cli/auth_login.py:348`.
   `NodeServices::prepare` (`crates/gdaemon/src/state.rs`) refuses to start a node without the
   `api_key` it writes. gclient has no login verb, and #21571 (Operator verbs on the client) starts
   only after all of Stage 2.
3. **SRT staging needs Python, and SRT itself runs on Node.js.** `src/gobby/cli/install_setup_srt.py`
   stages `@anthropic-ai/sandbox-runtime`, which `src/gobby/agents/srt_runner.mjs` runs under Node.js.
   #24374 (SRT install verification and the launch chokepoint) verifies the install and does not
   perform it. Node.js is neither Python nor Docker, but it is a non-Rust runtime a node needs.
4. **Global CLI hooks for interactive sessions on a node** come from `gobby install` (Python). Spawned
   runs are covered, because #24372 renders per-workspace hook config with the node's ghook.
