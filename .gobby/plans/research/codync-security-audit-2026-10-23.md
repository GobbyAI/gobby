# Codync security audit (2026-10-23)

Task #24827. Read-only audit by Security Reviewer gobby#17364 (session 735159c8, run de9945b3), delivered as four messages because that seat may not write files. The Orchestrator, gobby#17281, wrote and committed the text unchanged.

**Verdict: do not install on Josh’s primary account alongside Gobby at this revision.** Codync gives new bots automatic tool approvals, fetches executable agents from mutable registries, and silently advances installed connector packages. A separate defect leaves the local API token in SQLite without enforcing private filesystem permissions. Analytics starts enabled and links earlier anonymous activity to an account after sign-in. Hold the primary-account installation; an isolated VM with separate credentials is a reasonable evaluation environment with the mitigations below. Security verdict: **BOUNCE for installation as-is**. No malicious intent or actual compromise was established.

## Telemetry

**Yes: Codync phones home for analytics by default.** The main recipient is `https://us.i.posthog.com/batch/`. The host is enabled unless `analytics_enabled` equals `0`; it batches approximately every 30 seconds, retains up to 500 pending events and checks the setting before flushing. Debug host builds skip sending, so debug behavior does not establish release behavior (`host/src/analytics.rs:29–37,175–194,268–329`).

### Data and identity

- The host adds install/account identity, timestamp, event UUID, app version, environment, OS, architecture, a hashed computer identifier and session identifier. `$identify` merges earlier install activity into a signed-in Clerk user ID (`host/src/analytics.rs:213–265`).
- Usage includes message/turn activity, outcomes/duration, permission choices, routines, pairing, agents/models, connector and skill actions. The mapping constructs selected properties rather than uploading whole API bodies (`host/src/analytics/observe.rs:80–171`; `host/src/analytics/turns.rs:29–81`). Desktop events cover sign-in, onboarding, screens, links and voice engine selection (`apps/desktop/src/shared/analytics.ts:24–47`).
- Error reporting includes exception type, process, mechanism, functions, code file locations and line/column information. Runtime error messages are normally omitted; literal panic messages can be included (`host/src/analytics/errors.rs:53–106`). This review does not establish that third-party harness output is always secret-free.
- Desktop/TUI normally report through the host. Packaged desktop has a separate direct PostHog sender for `host_setup_failed` when its cached setting permits sharing, including a fresh install without stored state (`apps/desktop/src/main/analytics.ts:27–64`; `apps/desktop/src/shared/analytics.ts:49–54`).
- iOS and Android independently default to sharing, send directly and merge install events into signed-in account activity (`apps/ios/Kit/Sources/CodyncKit/Analytics/Analytics.swift:39–48,71–112`; `apps/android/app/src/main/kotlin/com/codync/android/Analytics.kt:47–98`). Project documentation describes MetricKit/iOS crash frames and Android exception frames, using the same switch (`docs/features/analytics.md:61–96`).

The policy says PostHog derives coarse location from source IP and discards the IP before storage. **Hosted settings cannot be verified from this clone.** The ingest service receives a network connection/source address regardless (`docs/features/analytics.md:21–35`). No Sentry, Amplitude or Mixpanel SDK integration was identified in the reviewed install/runtime surfaces.

### SDKs and disabling

Installed-app telemetry uses custom HTTP clients. The website uses **posthog-js 1.435.8** (`web/package.json`); `web/app/analytics.tsx:48–67` enables cookieless page views and explicit link/download clicks while disabling autocapture, session recording, surveys, performance capture and flag fetching. The website and installed app have separate settings. Clerk’s backend SDK is a cloud authentication dependency (`cloud/package.json`); desktop account HTTP is implemented directly (`apps/desktop/src/main/account.ts:145–161`).

1. Block PostHog **before first launch**, then turn **Settings → Share usage analytics** off in desktop. TUI exposes the switch through **Ctrl-K**; the host API is `setAnalytics` with `{"enabled":false}` (`host/src/api/host.rs:166–168`; `host/src/tui/app/analytics.rs:73–85`). No supported first-launch telemetry-off environment flag was found in the inspected implementation.
2. Disable it independently on every participating phone. Phones cannot change the computer owner’s setting (`host/src/api/devices.rs:31–42`).
3. Verify `hello.analytics` is false. Keep the egress block for a zero-transmission requirement. Disabling drops queued host events and cannot retract delivered events (`host/src/analytics.rs:296–301`).

The embedded computer-use driver explicitly receives `CUA_DRIVER_RS_TELEMETRY_ENABLED=0` and `CUA_DRIVER_RS_UPDATE_CHECK=0` (`apps/screen-macos/Driver.swift:22–34`; `host/src/screen/cua.rs:190–205`). Those flags do not disable Codync’s own analytics.

## Concrete mitigations and settings

Recommendations for a later operator-controlled evaluation; **none were executed in this audit**.

1. **Isolate the account and filesystem.** Use a VM/separate account without Josh’s home, Gobby state, production repositories, SSH agent or existing CLI credentials. Supply test credentials. `CODYNC_HOME` moves Codync state but does not isolate HOME or CLIs. Set every bot’s **Approvals to Ask**; leave computer/team-management integrations off. New bots inherit installed connectors/skills unless explicitly selected (`host/src/agent/new_bot.rs:13–29`), and new installs enable across existing bots (`host/src/market/mod.rs:215–245`).
2. **Protect state before initialization.** Pre-create `~/.codync` with mode 0700, use a restrictive umask and enforce owner-only database/WAL/SHM/token/identity files. Apply the equivalent to custom CODYNC_HOME. This mitigates other-user reads, not malicious code under the same account.
3. **Disable unused cloud access.** `codync-host cloud --disable` persists the setting. Runtime `CODYNC_CLOUD=off` works for foreground use. A foreground evaluation can use `CODYNC_CLOUD=off codync-host serve --bind 127.0.0.1`. The launchd installer captures PATH and CODYNC_HOME only, so exporting cloud-off while installing does not persist it into that service (`host/src/remote/cloud.rs:45–62,616–624`; `host/src/service/unix.rs:98–117`). Block egress until configured.
4. **Keep account approval at code.** The source warns that auto permits an account/cloud controller to add a device (`host/src/main.rs:116–120`). Pair only owned devices and revoke them after evaluation.
5. **Freeze executable changes.** Disable desktop automatic checks/downloads; disable standalone host auto-update with `codync-host update --auto off`. Avoid registry-backed connectors/automatic agent downloads: those refresh independently (F3). Use reviewed local artifacts/commands and limit their network access.
6. **Back up shared CLI configuration before launch.** Preserve `~/.claude/settings.json` and its permissions; compare Gobby hooks/settings after installation/removal. Codync wraps statusLine and rewrites the JSON. Uninstall attempts to restore the wrapped command (`host/src/main.rs:385–403,448–456`; `host/src/service/mod.rs:329–385`). No specific deletion of Gobby hooks was established. Avoid CLI install/login actions against Josh’s existing accounts.
7. **Avoid connector transport exceptions.** Use reviewed HTTPS endpoints; avoid custom HTTP and legacy SSE until F5 is fixed. Keep Composio, 1Password, provider voice and remote screen off until individually needed. Treat skills, repository instructions and tool output as untrusted even with Ask enabled.

## Installation, disk access and coexistence

The shell installer defaults to GitHub latest; CODYNC_VERSION selects a tag. It checks SHA-256 fetched from the **same release origin** as the artifact, without verifying the independently pinned host-update signature at bootstrap. Replacing both artifact and checksum at that origin defeats the check. The advertised curl-to-shell invocation also trusts mutable main before artifact checks (`packaging/install.sh:2,28–54`).

On macOS it mounts a DMG, quits Codync, removes/replaces `/Applications/Codync.app`, links codync-host into the bin directory and opens the app; sudo may be used for /Applications. Non-root host-only installation uses `~/.local/bin`, installs adjacent helpers when present and restarts an existing Codync service. It prints a PATH suggestion without writing shell rc files (`packaging/install.sh:43–45,63–101,143–145`). Desktop invokes its bundled host’s install command (`apps/desktop/src/main/host-controller.ts:169–184`).

The host installs a per-user launchd service with RunAtLoad/KeepAlive on macOS, or systemd user service on Linux, and logs to its data directory (`host/src/service/unix.rs:89–144`). Production state is normally `~/.codync`, development `~/.codync-dev`, with CODYNC_HOME override (`host/src/environment.rs:34–38`; `host/src/service/mod.rs:82–88`). State includes transcripts/config in codync.db, identity keys, bearer token, executable downloads, skills, uploads/workspaces and logs (F1 and the paths below). Service uninstall keeps data (`host/src/main.rs:448–456`).

## History and audit limits

Relevant changes include access renewal/recovery, Antigravity sign-in, advertised HTTPS addresses, Composio OAuth, analytics and one-click updates: 8e23502, 14861c2, f8c4fde, 8676e6a, f1e1664, 34bc12d, 75a2796. The depth-100 clone has 574 reachable commits because of merged histories. A local heuristic scan inspected **5,870 text blobs among 6,984 blobs** for private-key headers, GitHub tokens, AWS access IDs, common service-secret prefixes and JWT-shaped values. The only private-key-header match was `relay/test/fcm.test.ts:5–9`, which dynamically generates a test key; no fixed private key was identified. No credential-shaped value was found by those patterns. Binary blobs and text over 3 MB were omitted. Generic passwords, opaque credentials and history outside the shallow boundary are not excluded. No credential value is reproduced here.

All target inspection used Git reads and reviewer-authored parsing from the Gobby checkout. **No Codync executable/script, package-manager command, test, build or install was run; no external network request was made.** Dependency payloads, hosted privacy/infrastructure settings, release authenticity/notarization, the external Homebrew tap and current advisories remain unverified. The clone remains unchanged for Josh’s decision, as confirmed by the Orchestrator.

Gobby should avoid copying default-on account-linked analytics, automatic approval as the initial permission, lack of OS isolation around untrusted agent work, enabling integrations/credentials across bots by default, and silent replacement of reviewed executable dependencies.
