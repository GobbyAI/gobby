# Purge tmux from the codebase before the 1.0 port

## Overview
`kind: framing`

Epic #25486 (Purge tmux from the codebase before the 1.0 port), under #21542 (Gobby
1.0). Planning task #25577. Operator directive, 2026-11-01, relayed by the Assistant:
"we really need to purge tmux from the codebase before we start on the 1.0 port".
The epic blocks #25467 (Retire the Python runner) and #25468 (R0: Worker boundary and
frozen lifecycle contract), so it sits on the 1.0 critical path.

#22856 (closed 2026-10-04) removed every tmux spawn and launch path and kept three
external-tmux surfaces for sessions an operator starts by hand inside their own tmux:

1. gclient sidebar rows and orphan handling for hand-started tmux sessions;
2. the web viewer's shared tmux window sizing (#22362);
3. the external-tmux adapter: the hook and stdio proxy read `$TMUX`/`$TMUX_PANE`,
   `seed_external_terminal` upserts a `backend='tmux'`, `ownership='external'`
   terminal row, and send_keys, wake and the `/compact` continuation reach that pane
   through `tmux send-keys`, with the pane monitor, attach, observer and status
   pieces those use.

This plan removes all three, every module and branch that serves them, their config
keys, CLI flags, wire fields, stored values, tests, fixtures and docs. It also
removes every read of `$TMUX`/`$TMUX_PANE` as an environment fact, and it turns
off Gobby's terminal-control behavior for every session that no native terminal
hosts. After it lands, native gterm-hosted terminals (local and hub-remote, both
`backend='native'`) are the only terminal kind Gobby knows, and Gobby does not
care which shell or multiplexer a hand-started CLI runs in.

Operator rulings, 2026-11-03, relayed by the coordinator (gobby#19309), verbatim:
"Re: TMUX, we should remove all references to it. Gobby shouldn't care whether
it's launched on zsh or tmux, it just doesn't support those with send_keys and
should ignore the handoff rules outside gclient." Then: "That means when gobby is
running outside of gclient, no context pressure warnings, no set/get_handoff,
agents run however their CLI is set up to handle autocompaction." The coordinator
added Josh's clarification: a CLI hooked into Gobby outside gclient keeps its
hooks, tasks, closing, security and messaging rules; only terminal control is
off (Decision 15).

Sizing at HEAD `43d9b6f298` (2026-11-02), excluding `.gobby/plans`, re-verified
unchanged at `1931090650` and `454f23ef50` (2026-11-03):
`git grep -i -w tmux` hits 589 files and 3,069 lines;
`git grep -i tmux` hits 720 files and 6,396 lines. The extra 131 files carry
identifiers such as `tmux_pane`, `TmuxConfig`, `useTmuxSessions` and
`TMUX_TEXT_ENTER_DELAY_SECONDS`, which `-w` does not match because `_` and letters
are word characters (Decision 2). `git ls-files` lists 32 tracked files with
`tmux` in their path outside `crates/gterminal/vendor/`.

Every one of the 720 files is assigned: 647 belong to the 23 deliverables below,
and 73 untouched files fall in Decision 3's allowlist classes (18 vendored, 1
generated, 1 frozen baseline and 53 dated records). The deliverables
also target 19 consumers of removed or re-signed symbols that carry no tmux text,
plus new split modules, schema carriers and version files. A file with tmux text
in several outcomes has one owner per outcome, chained by dependencies.

## Decision Record
`kind: framing`

1. **Full purge, including the surfaces #22856 kept.** The operator's 2026-11-01
   directive supersedes #22856's KEEP list. A session an operator starts by hand in
   their own tmux becomes an ordinary unmanaged session, exactly like one started
   in any terminal emulator: it gets no terminal row, and send_keys, wake and the
   `/compact` continuation report that no managed terminal route exists. Since #22887,
   `src/gobby/events/wake.py` already reports a missing native route explicitly
   instead of falling back to raw tmux keys; the purge extends that behavior to
   every session. Gobby treats every terminal it does not host the same way,
   whether the CLI runs in zsh, bash, tmux or anything else: no code path asks
   which shell or multiplexer it is, send_keys is unsupported there, and the
   terminal-control rules of Decision 15 do not apply.
2. **The completion check has two parts.** The epic's criterion names
   `git grep -i -w tmux`. Whole-word matching misses 131 files of tmux identifiers
   (`tmux_pane`, `TmuxTerminalRuntime`, `TMUX_TEXT_ENTER_DELAY_SECONDS`, the
   `useTmuxSessions` hook) and every tmux-named file whose content has no hit. The
   plan checks both
   `git grep -i -l tmux -- . ':!.gobby/plans'`, which must list only Decision 3's
   allowlisted paths, and
   `git ls-files | grep -i tmux | grep -v '^crates/gterminal/vendor/'`, which must
   print nothing. A clean substring result implies a clean whole-word result, so
   the epic criterion holds.
3. **Legitimate mentions are four closed classes.** Gobby never starts, attaches
   to, polls, observes, detects or sends keys to tmux after this plan. Operator
   ruling 4 (2026-11-03) limits remaining mentions to vendored upstream code and
   frozen history, each stated by path; the coordinator dispositioned each path on
   2026-11-03 (gobby#19309, rulings A1-A5, superseding the earlier D1 and D2). A
   remaining mention is legitimate only in one of these classes, and the guard in
   7.1 lists each path:

     vendored upstream libghostty-vt Zig tree, including its tmux control-mode
     sources and the `tmux_control_mode` build option.
     `crates/gterminal/src/ghostty/bindings/generated_01.rs` is bindgen output of
     the vendored header (`GHOSTTY_BUILD_INFO_TMUX_CONTROL_MODE`). Editing either
     forks upstream (A1). `crates/gterminal/src/ghostty/mod/tests.rs` is Gobby's
     own test of that build option, so 4.6 scrubs it.
   - **Frozen schema history.** `crates/gcore/assets/schema/baseline.sql` is the
     canonical `baseline@420` snapshot pinned by `BASELINE_CHECKSUM` in
     `crates/gcore/src/schema/assets.rs`; migration 489 changes the live schema

     deletes the retired stored config rows once (Decision 6, A3), and

     and the 9 under `docs/reviews/`; `docs/audits/daemon-info-levels-2026-07-24.md`;
     and `.gobby/plans/`. 7.1's allowlist names every one of those files by path,
     not by directory. `docs/audits/configuration-audit.md` and

     edit them.
   - **The purge guard** (7.1), `tests/terminals/test_retired_backend_guard.py`,
     which must spell the pattern it forbids (A5).

   The recorded provider captures under `tests/fixtures/provider_contracts/` and
   `tests/adapters/test_agy_gate0_fixtures.py` are no longer allowlisted (operator
   ruling 2): 6.4 scrubs their provenance text. The environment reads Decision 7
   used to keep are removed by 4.6. Josh confirmed A2 and A4 on 2026-11-03
   (relayed by gobby#19309): `baseline.sql` is never edited, and every schema or
   data change goes through a forward migration (488, 489); dated history,
   changelogs, research notes and old plans stay as written, and only current
   documentation that claims or describes tmux support is updated.
4. **External ownership goes with tmux.** `seed_external_terminal` in
   `src/gobby/terminals/discovery.py` is the only production writer of
   `ownership='external'` terminal rows (sweep: `gcode grep -F "upsert_external" src
   crates tests`, 2026-11-02; every other caller is a test), and gclient treats an
   external row as a hand-started tmux session
   (`crates/gclient/src/app/live_loop/orphans.rs::is_orphan`). The purge removes the
   `external` ownership value end to end: `TerminalManager.upsert_external`, the
   Python and Rust ownership types, the gclient external-row handling, and the stored
   rows. The `backend` and `ownership` columns stay, each with one surviving value
   (`native`, `gobby`); hub remote terminals already use `backend='native'`
   (`src/gobby/hub/remote_spawn.py`). Collapsing those single-valued columns and the
   backend-keyed `TerminalRuntimeRegistry` is a separate simplification with no tmux
   content; the Stage 2 terminals port re-owns that family, so this plan leaves it.
5. **Two migrations empty and narrow the terminals table.** Migration 488 (1.1,
   Decision 6) first runs
   `UPDATE agent_runs SET terminal_id = NULL WHERE terminal_id IN (SELECT id FROM terminals WHERE backend <> 'native')`

   `agent_runs_terminal_id_fkey` has no `ON DELETE` action (`baseline.sql` line
   5373; `workspace_panes` already sets null on delete). Nothing after 1.1 creates

   `TerminalManager.upsert_external`, writes run-less external rows until 2.2
   deletes it. Every run-keyed resolver (`lifecycle_reconciliation.py`,
   `spawn_agent/_health.py`, `spawn_executor.py`, `_failure_cleanup.py` and the
   `TerminalServices.runtime_for` callers) therefore meets no tmux row after 1.1.

   table and on a live one without a pre-query. `baseline.sql` stays frozen

   (Decision 6) and 3.1 takes 489. If another migration takes either number first,
   the owning leaf uses the next free number and renames its file, its
   `MIGRATIONS` entry, its test names and the allowlist entry to match.

11. **Pane-owner, nested-child and subagent-child detection are deleted.**

14. **The memory sentence in the visual-capture reference is dropped.** Line 7 of
    `gclient-visual-capture.md` points at memory `06aaaa63` for a tmux preview

15. **Terminal control applies only to natively hosted sessions (operator rulings,
    2026-11-03).** A CLI session hooked into Gobby (Claude Code, Codex and the
    rest) that no native gterm terminal hosts, whatever its shell, is tracked as
    today and keeps its hooks, tasks, closing, security and messaging rules. Only
    terminal control is off for it: no context-pressure warnings or injections, no
    block at the context limit, no `set_handoff` or `get_handoff` demand, no
    handoff turn-end hold, and no Gobby-driven `/compact`, `/clear` or
    continuation through send_keys. The provider CLI's own autocompaction runs as
    its user configured it.
    - **Signal.** `TerminalManager.resolve_live_for_session(session)`
      (`src/gobby/storage/terminals.py`) returning a row means the session is
      hosted; `None` means it is not. After 3.1 every stored row is
      `backend='native'`, `ownership='gobby'`, so presence or absence of a live
      bound row decides, and no code asks which backend or owner the row has.
      Headless spawned agent runs have no terminal row and fall on the unhosted
      side (their CLI compacts itself). Web chat sessions compact in process and
      are unchanged; the check applies to `session_type == 'terminal'` only.
    - **Carrier.** A new observer writes the reserved session variable
      `native_terminal_hosted` (`True` or `False`) at session start and turn
      start for terminal sessions, and leaves it unset for web chat or when the
      handler has no terminal manager, so those keep today's behavior.
    - **Rules.** Every bundled rule that warns about context pressure or demands a
      handoff at the context limit selects on that variable generically, with no
      definition names: `variables.get('native_terminal_hosted') is not False`.
      The rules that act only on a staged handoff (the pull gate, the turn-end
      hold after staging and the delivery retry) stay ungated: only a hosted
      `set_handoff` arms them, and a pending pull must still be consumed if the
      row later reads unhosted. The pressure
      observers write no guidance, band or block message when it is `False`, so
      no stale state survives a later bind.
    - **Already true, pinned by tests.** `set_handoff` on a terminal session with
      no live native terminal returns `terminal_target_unavailable` before staging
      anything (`_compact_with_handoff` in
      `src/gobby/mcp_proxy/tools/sessions/_terminal.py` resolves the pane before
      `stage_handoff_attempt`), so `handoff_pull_pending` and
      `_handoff_turn_end_pending` are never armed for such a session, and the
      compact and clear pull prompts, which type into the session's native pane,
      have nowhere to go. 3.2 pins the refusal for both `clear_session` values.
    Rules about tasks, closing, security, messaging, skills and memory are
    unchanged.
