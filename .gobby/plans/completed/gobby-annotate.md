# Gobby Annotate

**Plan ID:** gobby-annotate

## Overview
`kind: framing`

Build a compact annotation extension for desktop Chrome, desktop Safari, and Safari on iPhone/iPad. Users select elements or regions, add comments, and export JSON plus screenshots.

The standalone MCP server uses stdio. Gobby launches, connects to, and manages that server through its existing MCP connection system. The annotation skill discovers and calls its tools through Gobby’s proxy, then creates Gobby tasks.

## Constraints
`kind: framing`

- Develop inside `gobby-annotate/`, inheriting Gobby’s branding and license.
- Write the implementation independently; Drawbridge remains reference-only.
- Use TypeScript/React for the extension, TypeScript/Node.js for MCP, and Swift for Safari packaging and save/share.
- Extension and MCP remain usable without Gobby.
- Operate on the page’s actual viewport. No iframe workbench or built-in viewport emulation.
- Save drafts locally and export explicitly. No cloud service, automatic folder sync, telemetry, or status synchronization back into the extension.
- Preserve `/gobby bridge` for Drawbridge. Introduce `/gobby annotate`.
- Deliver development-installable builds; store submission is outside this plan.
- Reuse existing UI primitives without modifying other sessions’ shared UI work.
- Keep production modules below 1,000 lines.

**Implementation domain:** backend.

Export ZIP files containing `capture.json` and referenced PNG screenshots. An extracted directory is an equivalent input.

Define a versioned manifest containing stable batch ID, unique export ID, title, export timestamp; annotation ID, revision, timestamps, comment; page URL/title and frame identity; element or rectangle target, locator/context and bounds; layout/visual viewport, pixel ratio and scroll position; screenshot reference/dimensions or an explicit unavailable reason.
