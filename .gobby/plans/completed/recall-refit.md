# Recall Refit: Why the Digest-Label Experiment Failed and What to Change

## Context

Epic #17099 / task #17811 tried to replace static recall-ranking constants with fitted ones. The plan: label injected memories useful/not-useful via a digest judge (`label_source='digest'` rows in `recall_usefulness`), build **within-request preference pairs** (one useful + one not-useful hit in the same recall request), and run a ship gate requiring ≥50 train / ≥20 holdout pairs. After a week of healthy collection (18/18 injected memories labeled, no judge failures): 35 joinable labels, 33 not-useful / 2 useful, **0 pairs**. Successor #18375 (due 2026-08-17) says: do not do another time-only retry; change fit-valid pair acquisition instead. Guardrail tasks #18376 (request-level effective sample size) and #18377 (delayed-label candidate content identity) were closed 2026-07-18 as duplicates of this plan's coverage — the effective-sample-size gate and content-identity admission below are the binding requirements, and their guardrail tests land with this work.

## Diagnosis (from live DB, 2026-07-17)

Three stacked causes, each independently fatal to pair formation:

1. **Injection cardinality vs pair rule mismatch.** Labels only exist for *injected* memories, and injection is 1–2 per request (17 requests with 1 label, 11 with 2). A pair needs mixed classes in one request. Both useful labels landed in single-label requests — structurally unpairable. All 11 two-label requests were uniformly negative.
2. **~5% positive base rate from a usage-based judge criterion.** The digest judge asks "did the response visibly use the TARGET memory's specific content" — a much stricter bar than relevance. Ambient-context memories almost never produce verbatim transfer into one response.
3. **Upstream recall relevance is genuinely weak.** Injection outcomes: 70 injected vs 4,817 filtered ("other"). Several judged-negative rationales show topically unrelated recalls. Refitting 4 ranking constants can't rescue consistently irrelevant candidate pools — separate follow-up, not this plan.

**Key enabling asset:** `recall_signal_hits` already logs the full scored candidate list per request — 11,781 rows across 1,367 requests, mostly 8 (range 5–20) candidates per request, each with the complete feature vector. `recall_signal_requests` stores the query text and per-candidate score maps. Only labels for non-injected candidates are missing.

## Recommended change

**Shadow candidate judging against the stored query, over durable hub rows.** During the digest pass, poll `recall_signal_requests`/`recall_signal_hits` for this session's requests lacking complete `digest_shadow` labels, and judge the full scored candidate list (top-8 by rank) for **relevance to the stored `query` text** — one comparative LLM call per request, one label row per candidate under isolated `label_source='digest_shadow'`. The judge never sees the assistant response (no post-treatment leakage, no echo advantage for injected candidates); query-relevance is the textbook LTR target for fitting *ranking* constants. Fit validity is protected by a **centralized cohort query builder** (one immutable candidate-eligibility layer shared by all phases, plus phase-specific label state: polling = missing/due, fitting/drift = complete, audit = any) and: exact protocol-version fencing, single weighting-regime per fit, single judge-model per fit (both fail closed with per-cohort counts on ambiguity), content-identity admission (at-recall hash must match at judge time), complete-request-only fitting with atomic mapping-verified label persistence and a durable claim/lease state machine, per-request weight normalization with request-unit shrinkage selected without touching holdout, mixed-request floors as the effective-sample-size gate (#18376), and a **gate-reconstructed human audit** — the gate deterministically rebuilds the audit sample, requires all bound human verdicts, recomputes agreement, and fails closed, so the audit is a hard gate input rather than an advisory CLI step. User-visible injection behavior unchanged. This **replaces the digest-usage judge outright** — the shadow relevance judge becomes the single memory-usefulness stream feeding the fit; the ablation/`llm_judge` stream is separate and untouched.

**Removed in this change** (rule 16, pre-0.5.0 — no dead code, no backward-compat): the digest-usage judge and everything only it used — `USEFULNESS_RUBRIC` and the usage-judging body of `judge_pending_memory_usefulness` (`usefulness.py`), the `_queue_memory_usefulness` feed and `pending_memory_usefulness` session var (`workflows/engine/effects.py`), the `memory.digest_memory_usefulness` config flag, and the `'digest'` writer. The `'digest'` **producer** is retired, but its ~35 rows are **preserved as read-only historical evidence** — they justify this redesign (provenance, not backward-compat), so migration 323 keeps `'digest'` valid in the label-source CHECK and never deletes the rows; only the *writer* is removed (nothing emits `'digest'` again). It is structurally fit-incapable (~5% positives, 0 pairs) and superseded by shadow.

**Dropped:** skip-above pairs (needs a recorded exposure/reference signal — follow-up only after one is captured); raising `selected_limit`; cross-request pairs; historical backfill (pre-hash hits lack content hashes, so backfill waits on #18377 semantics).

## Implementation steps

1. **Content identity at the capture layer + migration + contract.**
   - `emit_search_debug` (`services/_search_debug.py:15`): compute `content_hash = sha256(utf8(Memory.content))` per hit — **exact UTF-8 bytes of the full stored content, no normalization** (nothing to version; judge-prompt truncation happens downstream and is covered by the protocol version). Carry through `SearchDebugHit` → `build_recall_signal_event` (`recall_signal_log.py`, signal schema version bump) → `insert_signal_event` → `recall_signal_hits.content_hash`. **Also stamp `recall_signal_requests.constants_provenance`** at recall time: `resolve_recall_constants` (`recall_constants.py:126`) returns the active constants plus a provenance id — `'static'`, or the `decision_digest` of the shipped decision when `use_fitted_recall_constants` is live — which the request write records, so drift can later select exactly the requests ranked by the fitted constants.
   - `src/gobby/storage/migrations/323_recall_usefulness_digest_shadow.sql`: **preserve existing `label_source='digest'` rows as read-only historical evidence** (they justify this redesign — provenance, not compat) and **widen** the CHECK to `('llm_judge','ablation','digest','digest_shadow','human')` — `'digest'` retained for the historical rows, `'digest_shadow'` added; `content_hash text` on `recall_signal_hits`; new table `recall_shadow_judge_state` (PK `(recall_request_id, label_source, judge_protocol_version)`; `status IN ('claimed','retryable','terminal','complete')`, `attempts int`, `next_attempt_at timestamptz`, `lease_expires_at timestamptz`, `claim_token text`, `last_error text`, `updated_at`); **new immutable snapshot table `recall_shadow_prompt_snapshot`** (PK `(recall_request_id, label_source, judge_protocol_version)`; `system_prompt text` [exact `SHADOW_RELEVANCE_RUBRIC`], `query_text text`, `presented jsonb` [ordered `{neutral_key, memory_id, order_index, excerpt, content_hash}`], `prompt_hash text`, `judge_model text`, `judge_config_fingerprint text` [pinned model + generation settings], `created_at`) — the exact, replayable reviewer-facing record of what the judge saw; **new authoritative audit-verdict table `recall_shadow_audit_verdicts`** (unique `(cohort_digest, request_id, memory_id)`; `cohort_digest text`, `sample_digest text`, `request_id`, `memory_id`, `prompt_hash text`, `human_verdict boolean`, `reviewer text`, `created_at`) — the sole store of human ship-audit verdicts, because the `recall_usefulness` table has no `prompt_hash`/sample identity and the wrong unique key (`(request, memory, source, protocol)`); **new gate-run table `recall_gate_runs`** (PK `holdout_consumption_key text`; `status text IN ('reserved','complete')`, `fit_settings_digest text`, `claim_token text`, `lease_expires_at timestamptz`, `attempts int`, `last_error text`, `ship boolean`, `decision jsonb`, `created_at`) and **`recall_holdout_consumed`** (`request_id` **unique**, `holdout_consumption_key text`, `consumed_at`) — together make holdout isolation structural at the **request-ID** level: a request used for holdout once is permanently burned from future holdout use (a protocol bump cannot re-evaluate it), though it may later join a *training* cohort; **`constants_provenance text` on `recall_signal_requests`** (stamped at recall time — `'static'` or the active shipped-decision digest — so drift can select requests actually ranked by the fitted constants); index on `recall_usefulness (recall_request_id, label_source, judge_protocol_version)`.
   - `LABEL_SOURCES` (`recall_signals.py:47`): the valid set keeps `"digest"` (historical rows) and gains `"digest_shadow"`; a separate `PRODUCIBLE_LABEL_SOURCES` write-side allowlist **excludes** `"digest"` (nothing may emit it again) — inserts validate against the producible set, the DB CHECK against the valid set.
   - Amend the contract: mark `'digest'` **retired / read-only historical** and add `'digest_shadow'` in the §6 enum (the digest value stays documented; its producer is gone); new §4 subsection — comparative query-relevance semantics over the full scored candidate list, response never shown, the same position/length de-biasing guards but **no different-model-family requirement** (no defined comparator; query-only judging already removes response echo); document the admission predicate, all fences (label source, protocol version, judge-model key, judge-config fingerprint, regime, candidate scope, and the dual request/completion cutoffs), the content-identity rule (#18377), the **immutable presentation snapshot** as the sole audit-of-record (reviewers reconstruct nothing from live memories), and the dedicated **`recall_shadow_audit_verdicts`** store (keyed `(cohort_digest, request_id, memory_id)`, carrying `sample_digest` + `prompt_hash`) as the authoritative home for human ship-audit verdicts.
2. **Store API (`src/gobby/storage/recall_signals.py`).**
   - **Centralized cohort SQL, split by phase:** a parameterized query builder `shadow_cohort_query(phase, ...)` with two layers. *Immutable candidate eligibility* (shared by every phase): `caller='memory.recall'`, nonblank `query`, supported signal `schema_version`, non-null `content_hash` on all top-min(n_hits, 8) hits, source filter. *Phase-specific label state*: `polling` = eligibility ∧ labels missing/incomplete ∧ state due; `fitting`/`drift` = eligibility ∧ exact top-k label completeness for (source, exact protocol **+ judge-config fingerprint**) ∧ single regime ∧ single judge model; **`audit_scored` = the same completeness fence as `fitting` (complete labels + committed immutable snapshot)** — scoring requires a committed snapshot, which incomplete/claimed/retryable requests lack; a separate **`audit_status`** report (not a scored cohort) enumerates claimed/retryable/terminal/incomplete requests. No consumer re-derives cohort membership; the phases differ only in the label-state parameter.
   - `fetch_unshadowed_requests(session_id, *, label_source, judge_protocol_version, limit)` — the `polling` phase: eligible requests with labels missing, excluding `terminal`/`complete` state, `claimed` state with an unexpired lease, and `retryable` state not yet due.
   - **Claim lifecycle** (prevents duplicate judging despite the lock being released during the LLM call): transitions `due → claimed → complete | retryable | terminal`. Claiming (short `transaction_immediate` under a concrete typed `LockTarget` dataclass, `ShadowJudgePoll(session_id)` with assigned `PRIORITY` per `hub/protocol.py:53`) sets `status='claimed'`, a fresh `claim_token`, and `lease_expires_at = now + 10 min`; expired leases are reclaimable. **The poll loop claims exactly one request immediately before its own LLM call and repeats up to 8 times per pass — never claiming all 8 up front** — so each 10-min lease covers only that request's active judging, and a later request's lease cannot expire while earlier ones are still being judged (which would let another poller reclaim it into duplicate work and stale-token failures). The LLM call runs outside any transaction. Judge-time content identity checked under the claim: drift/deletion → `terminal` (`content_drift` | `memory_deleted`); structurally invalid responses → `retryable` with exponential backoff (`next_attempt_at = now + min(2^attempts, 24) h`) so a flaky request cannot monopolize the 8-request poll cap.
   - `insert_usefulness_labels_atomic(rows, snapshot, claim_token)` — one transaction that (a) verifies the state row still holds this `claim_token` (zombie claimants abort), (b) inserts one row per presented candidate **and writes the immutable `recall_shadow_prompt_snapshot` row in the same transaction** (labels and the presentation-of-record commit together or not at all), then **reads back the full `memory_id → judge_useful` mapping and compares it element-wise to the expected mapping** (equal row counts can still hide a conflicting verdict, so count checks are insufficient), and (c) sets `status='complete'`. On mismatch the transaction rolls back via savepoint; the follow-up retry marks the claim `retryable` with `UPDATE ... WHERE claim_token = <failing_token>` and **asserts exactly one row updated** — an expired zombie whose token was superseded by a newer claim updates zero rows and leaves the newer claim untouched.
   - `fetch_replay_rows(..., candidate_scope, judge_protocol_version, weighting_regime_key, judge_model_key, judge_config_fingerprint, data_cutoff, completion_cutoff)` — restricts to `request.created_at <= data_cutoff` **and** `snapshot.created_at <= completion_cutoff` (the delayed-completion freeze); **content-hash + complete-top-k request admission is keyed on `label_source='digest_shadow'`, never on `candidate_scope`** (an explicit `digest_shadow`/`injected` call is still admitted; `candidate_scope` only selects which rows of already-admitted requests project into the replay set). Non-shadow `label_source` values are outside this change and their query path is not modified. `"full"` LEFT-JOINs outcomes; `weighting_regime_key`, `judge_model_key`, and `judge_config_fingerprint` are required filters for fitting; ambiguity in any fails closed with per-regime / per-model / per-fingerprint cohort counts. Limits are request-aligned (count requests, never truncate one).
   - `sample_usefulness_labels(*, label_source, protocol_version, judge_model_key, judge_config_fingerprint, regime_key, candidate_scope, n_requests, data_cutoff, completion_cutoff, mode, since)` — draws from the **`audit_scored` cohort**: the exact fenced shadow cohort (all six keys) with **complete labels + committed immutable snapshot**, `request.created_at <= data_cutoff` and `snapshot.created_at <= completion_cutoff` (identical to what the gate fits — scoring requires a committed snapshot, which incomplete/claimed/retryable requests do not have). **`mode='ship'`**: **uniformly** sample `n_requests` distinct requests and **uniformly** select one target candidate per request — independent request units, so a plain request-balanced statistic is valid (no weighting). **`mode='diagnostic'`**: rank-band × verdict oversampling of rare cells (predicted-positives), returned for per-cell visibility only and **never mixed into the ship statistic**. Either mode returns each request's **`recall_shadow_prompt_snapshot`** (system prompt, query text, presented excerpts, neutral keys, order, judge model, judge-config fingerprint, hashes) so the reviewer scores exactly what the judge saw — **never live memory content**, which may have drifted or been deleted since. `since` is honored **only** in `mode='diagnostic'` and the status report — **never in `mode='ship'`**, whose population is fixed entirely by the cohort identity the gate reconstructs (an extra `since` filter is unfenced, absent from `cohort_digest`, and would desync the audit sample from the gate). A **separate `audit_status` query** (not the scored sample) reports claimed / retryable / terminal / incomplete requests for operational visibility.
   - `insert_audit_verdicts(rows, *, cohort_digest, sample_digest)` and `fetch_audit_verdicts(cohort_digest, sample_digest)` on **`recall_shadow_audit_verdicts`** — the authoritative human-verdict store. The gate fetches by exact `(cohort_digest, sample_digest)` and rejects any row whose `prompt_hash` no longer matches the target's committed snapshot; human verdicts never touch `recall_usefulness`.
   - `reserve_gate_holdout(*, holdout_consumption_key, fit_settings_digest, holdout_partition_ids)` — the **atomic reservation** (one `transaction_immediate` under a typed `GateHoldoutReservation` lock, run **before any holdout is read**): returns the stored decision on a `complete` row with matching `fit_settings_digest`, **rejects** a conflicting digest, else selects `holdout_partition_ids` **minus every `request_id` already in `recall_holdout_consumed`**, inserts those into `recall_holdout_consumed` (unique per `request_id`) and a `recall_gate_runs` row `status='reserved'` with a `claim_token`, and returns the reserved set (fails closed if it can't clear `MIN_EVAL_MIXED_REQUESTS`). A later `complete_gate_run(key, claim_token, ship, decision)` flips the row to `complete`.
3. **Fit changes (`src/gobby/memory/recall_fit.py`).**
   - Per-request normalization by scope: shadow/full — each pair weighted `1/(P·N)` (complete labels ⇒ uniform exposure ⇒ position-IPS irrelevant); usage/injected — `IPS(pos)/(N·ΣIPS(pos))` so each request sums to exactly 1 preserving relative IPS. `weighting_mode` recorded in provenance.
   - `shrinkage_pairs` → `shrinkage_requests`: `lam = mixed_requests/(mixed_requests + shrinkage_requests)`. **Default selected without touching holdout:** sweep request-unit priors (2, 5, 10, 20, 50) on synthetic data plus nested validation *within training requests only* (the benchmark gains these arms); freeze the selected value **before** any holdout evaluation, then evaluate holdout exactly once in the gate. All selection runs on training requests within the frozen `data_cutoff` (the same upper `created_at` bound audit and gate use). Selection method, training cutoff, and chosen value recorded in decision provenance.
   - `PairwiseEvalResult` gains `mixed_request_count`; raw pair counts reported separately from effective units. No skip-above.
   - The **train/holdout split is deterministic** (seeded by request id) and **versioned**; the split + evaluator version **and `audit_sampler_version`** are folded into the `cohort_digest`, so the ship-audit sample (**training partition only**), shrinkage selection, and the once-only holdout evaluation all bind to the same frozen partition — a failed audit can revise the rubric without ever having observed a holdout request.
4. **Gate plumbing (`src/gobby/memory/recall_refit.py`).** `run_ship_gate(_from_store)` gain `candidate_scope`, required `judge_protocol_version`, required `weighting_regime_key`, required `judge_model_key`, **required `judge_config_fingerprint`** (generation settings — fails closed with per-fingerprint counts if the cohort mixes fingerprints, so a temperature/top-p change cannot silently pool under one model/protocol; equivalently an effective protocol key = protocol version + fingerprint), and **two frozen cutoffs — `data_cutoff=T` (`request.created_at <= T`) and `completion_cutoff=L` (`snapshot.created_at <= L`, the delayed-completion freeze)** — both **frozen before the audit and passed identically to audit, replay, shrinkage selection, and gate**, so every phase observes exactly one population: a pre-`T` request whose labels/snapshot commit after the audit but before the gate is excluded by `L`, and later-created requests are excluded by `T`. Scope resolution: `default_candidate_scope(label_source)` → `"full"` for `digest_shadow`, `"injected"` otherwise; CLI `--candidate-scope` overrides. Data-floor gate: raw pair floors 50/20 (unchanged) **and** mixed-request floors `MIN_TRAIN_MIXED_REQUESTS=20` / `MIN_EVAL_MIXED_REQUESTS=10`. `GateDecision.to_record()` carries the full cohort definition: label source, protocol version, judge model key, **judge config fingerprint**, candidate scope, regime key, **both frozen cutoffs `data_cutoff=T` and `completion_cutoff=L`** (recorded verbatim, never recomputed at gate time — `T` on `request.created_at`, `L` on the delayed `snapshot.created_at`, never the raw `labeled_at`), weighting mode, shrinkage value + selection method, evaluator version, floors, mixed-request counts. Both eval arms use identical pairing/normalization. **Gate-enforced human audit (the audit is a hard input, never advisory):** before emitting `ship: true`, `run_ship_gate` calls the shared deterministic `build_ship_audit_sample(cohort)` (in `recall_refit.py`, used by both this gate and `audit-labels`), which samples **only the deterministic training partition** — never holdout, so a failed audit that triggers rubric revision cannot contaminate the once-only holdout evaluation. The sample is seeded **solely by the frozen cohort identity** — all fences + `T` + `L` **plus the split + evaluator version**, hashed to a **`cohort_digest`** — so the CLI and the gate select the identical 50 training request-target pairs with no fresh randomness. The gate then loads the human verdicts from **`recall_shadow_audit_verdicts`** for that exact `cohort_digest` + `sample_digest`, verifies each row's `prompt_hash` against the target's committed snapshot, **requires all 50 present, recomputes point agreement and the Wilson 95% lower bound itself** (never trusting CLI-reported numbers), and **fails closed**: a <50-train-scored cohort, any missing / stale-hash / cohort-or-sample-digest-mismatched verdict, or a bound below the precondition yields `ship: false`. `to_record()` additionally records the **`cohort_digest`**, **`sample_digest`** (hash of the selected `(request_id, target_memory_id, prompt_hash)` tuples), audited **unit count**, recomputed **agreement**, **Wilson lower bound**, and **audit status**. **Holdout isolation is structural at the request-ID level, reserved atomically before any holdout is read:** the gate computes a **`holdout_consumption_key`** = hash of the **non-tunable** cohort identity (label source, protocol version, judge-model key, judge-config fingerprint, regime, candidate scope, `T`, `L`, split + evaluator version — **excluding** shrinkage and every tunable knob) and a `fit_settings_digest` of the tunable settings actually used. In a single `transaction_immediate` under a typed `GateHoldoutReservation` lock — **before loading any holdout data** — it resolves the existing `recall_gate_runs[key]` row: a **`complete`** row returns its stored decision on a matching `fit_settings_digest` and **rejects** a conflicting one (shrinkage cannot be shopped); a **`reserved`** row with an **unexpired `lease_expires_at`** means another run holds it → back off; a **`reserved`** row whose **lease has expired** (a crashed run) is **reclaimable only by the same `fit_settings_digest`** — it **reuses the identical already-reserved holdout IDs** (bound to the key in `recall_holdout_consumed`, so a crash between reservation and completion never permanently burns them), takes a fresh `claim_token`, bumps `attempts`, and refreshes the lease; a conflicting `fit_settings_digest` on an expired reservation is still rejected. Absent any row, it selects the **disjoint** holdout set — this cohort's deterministic holdout-partition requests **minus every `request_id` already in `recall_holdout_consumed`**, so a protocol bump (a fresh key over the same partition) can never re-evaluate previously-exposed holdout requests — inserts those IDs into `recall_holdout_consumed` bound to the key, and writes the gate-run row `status='reserved'` with a `claim_token` and `lease_expires_at`. Only **after** this atomic reservation does it load and evaluate the reserved holdout exactly once, then flip `status='complete'` with `ship` + `decision`; on evaluation failure it records `last_error` and leaves the reservation reclaimable after lease expiry. Concurrent callers with different settings cannot both read holdout — the loser is rejected during reservation. If too few un-consumed holdout requests remain to clear `MIN_EVAL_MIXED_REQUESTS`, the gate fails closed (`insufficient_holdout`). Previously consumed holdout requests may still enter later **training** cohorts. **Serialization contract:** `to_record()` serializes via canonical JSON (sorted keys, UTF-8, normalized number formatting); the **`decision_digest`** is that canonical hash **excluding the `decision_digest` field itself**, tagged with a recorded `decision_schema_version`; `build_ship_audit_sample` records an `audit_sampler_version` that is folded into `cohort_digest`, so a sampler-algorithm or schema change mints a new identity rather than silently reusing holdout or a stale sample.
5. **Shadow relevance judge (new module `src/gobby/memory/shadow_relevance.py`, renamed from `usefulness.py` — the old name described the dead pending-queue/usage semantics).** `SHADOW_RELEVANCE_RUBRIC` — counterfactual helpfulness for the stored request query only; specific facts/paths/commands/conventions bearing on the request beyond what it states; word overlap ≠ relevance; ignore length/style/order; JSON verdicts `{key, relevant, confidence, rationale}`. **One exported constant** `SHADOW_PROTOCOL_VERSION = "digest-shadow-query-relevance-v1"` — imported by the CLI, tests, and drift; no string literals elsewhere. `_build_shadow_prompt` shuffles deterministically (seed = request id), neutral keys `M1..Mn` post-shuffle, and returns the **presentation record** alongside the prompt — exact system prompt (`SHADOW_RELEVANCE_RUBRIC`), query text, per-key `{memory_id, excerpt, order_index, content_hash}`, presentation order, pinned-judge `judge_config_fingerprint` (model + generation settings), and `prompt_hash` = sha256 of the exact prompt string sent — a complete, replayable record of the judge invocation. `_judge_shadow_entries`: per claimed request — verify content identity, one `call_json_feature`, persistence via `insert_usefulness_labels_atomic(rows, snapshot, claim_token)` (labels + immutable snapshot commit together). **Judge-model provenance fixed:** `_judge_model_label` (:72) records `labels[0]` — the first *configured* candidate, not the routed model. Shadow judging pins one judge candidate with fallback disabled (fail → `retryable`, never a silent fallback model), records the actual routed provider/model as `judge_model` and the `judge_config_fingerprint`. **No different-model-family rule** — it has no defined comparator; query-only judging (the response is never shown) already removes response-echo/self-preference, and the pinned model + config fingerprint supply reproducibility. The public entry point is **`judge_shadow_candidate_relevance`** (replacing `judge_pending_memory_usefulness`); the usage-judging body and `USEFULNESS_RUBRIC` are deleted (not kept as a second stream); the digest-pass call site (`digest.py:882`) now drives durable polling — claiming one request immediately before each of up to 8 LLM calls per pass under the typed lock (lease covers only active work) — instead of the session-var queue. **Delete the dead queue feed** `_queue_memory_usefulness` and `pending_memory_usefulness` in `workflows/engine/effects.py` — shadow reads durable hub rows, so nothing enqueues.
6. **Config + drift.** In `MemoryConfig`: **remove `digest_memory_usefulness`**; add `digest_shadow_usefulness: bool = False` with a **model validator enforcing `recall_signal_hub=true`** (fail closed at startup, not prose). 7. **CLI (`src/gobby/cli/memory/signals.py`).**
   - `gobby memory recall-signals gate --label-source digest_shadow --protocol-version <SHADOW_PROTOCOL_VERSION> --regime-key K --judge-model-key M --judge-config-fingerprint F --data-cutoff T --completion-cutoff L [--candidate-scope injected|full] [--write-decision [PATH]]` — `--data-cutoff T`, `--completion-cutoff L`, and `--judge-config-fingerprint F` (all **identical to the audit's**) are required; prints `GateDecision.to_record()`, exit 1 on reject; regime, judge-model, or judge-config-fingerprint ambiguity lists the respective per-cohort counts.
   - `audit-labels --label-source digest_shadow --protocol-version V --judge-model-key M --judge-config-fingerprint F --regime-key K --candidate-scope full --data-cutoff T --completion-cutoff L --n-requests 50 [--record-agreement]` — all cohort fences (**including `--judge-config-fingerprint`**) **and both frozen cutoffs `--data-cutoff T` / `--completion-cutoff L` (identical to the gate's)** are required; the scored sample and the agreement join both run against the `audit_scored` cohort — complete labels + committed snapshot, `request.created_at <= T` and `snapshot.created_at <= L` — and the reviewer scores from the **presentation snapshot** (never live memory). **Ship statistic — deterministic, training-partition sample:** the sample comes from the shared `build_ship_audit_sample(cohort)` (seeded by the frozen cohort identity + split/evaluator version, **not** fresh randomness) — 50 distinct **training-partition** requests (never holdout), one target each; a single shadow call emits up to 8 correlated verdicts, so the request is the independent unit and one-per-request keeps the 50 units independent. `--record-agreement` writes each human verdict to the authoritative **`recall_shadow_audit_verdicts`** table, keyed `(cohort_digest, request_id, memory_id)` and carrying `sample_digest`, the target's `prompt_hash`, the verdict, reviewer, and timestamp — a verdict is valid only against the exact presentation it scored — and previews the **request-balanced agreement** with a plain **Wilson 95% interval**. **The gate, not this command, is authoritative:** `run_ship_gate` reconstructs the identical sample, loads verdicts by exact `(cohort_digest, sample_digest)`, requires all 50 with matching `prompt_hash`, recomputes the statistic, and fails closed. **Predeclared ship precondition (enforced by the gate): point agreement ≥80% AND Wilson 95% lower bound ≥65% over the 50 bound request units.** Below that → revise the rubric under a bumped protocol version. **Separately**, a `--diagnostic` rank-band × verdict oversample (ranks 1–4 vs 5–8, including rare predicted-positives) — **restricted to training requests, like every pre-gate diagnostic (holdout is never observed before the single gate evaluation), observational** — surfaces per-cell agreement for visibility but is **excluded from the ship statistic**; low positive prevalence stays diagnostic, never blocks shipment.

## Rollout

1. Land everything dark (`digest_shadow_usefulness` defaults false; new hits start carrying `content_hash` immediately — pre-hash hits are never shadow-judgeable, which is correct under #18377).
2. Flip `memory.digest_shadow_usefulness=true` (validator enforces `recall_signal_hub`). Collect until observed **mixed-request counts** approach the floors (20 train / 10 holdout) — no calendar promise; the observed mixed-request rate is the go/no-go signal for the design itself.
3. **Freeze both cutoffs — `data_cutoff = T` (request-creation) and `completion_cutoff = L` (snapshot-commit)** — and audit at them: `audit-labels --label-source digest_shadow --protocol-version <SHADOW_PROTOCOL_VERSION> --judge-model-key <observed> --judge-config-fingerprint <observed> --regime-key <observed> --candidate-scope full --data-cutoff T --completion-cutoff L --n-requests 50 --record-agreement`. Proceed only when the predeclared uniform request-balanced agreement precondition holds; otherwise revise the rubric under a bumped `SHADOW_PROTOCOL_VERSION` (protocol fencing makes old labels inert, not poisonous).
4. Select shrinkage via the synthetic/nested-train sweep (within the same `T`/`L`) and freeze it **before** any holdout evaluation. Then `gate --label-source digest_shadow --protocol-version <constant> --regime-key <observed> --judge-model-key <observed> --judge-config-fingerprint <observed> --data-cutoff T --completion-cutoff L --write-decision` — **the same `T`, `L`, and fingerprint as the audit**, so audit, shrinkage selection, and gate share one population (no pre-`T` request completing after `L` leaks in); the gate evaluates holdout exactly once **and reconstructs the deterministic audit sample, requiring all 50 prompt-hash-bound human verdicts and recomputing the agreement bound — no valid audit ⇒ `ship: false`**. The gate persists an immutable `recall_gate_runs` row keyed by `holdout_consumption_key`; **re-tuning shrinkage (or any fit setting) requires a new protocol/cohort — you cannot re-evaluate holdout to shop for a pass**. Ship only on `ship: true`.

Drift monitor picks up the shipped cohort definition automatically and evaluates **only provenance-matched requests** (never a time window), so rollback/re-enable cycles never mix static- and fitted-ranked requests.
