# Adversarial Review: Wake Delivery Recovery

Reviewed plan SHA-256: `4c6e599fd94dd9a0afe2cd1e83527aa65c7683f4c0a1588d80185bc08f3752a3`.

1. **BLOCKING — The restart reconciliation predicate can pause a genuine in-flight turn.** The plan treats an `empty` or `draft` composer as positive proof of provider idleness and relies on an `updated_at` CAS (`.gobby/plans/wake-delivery-recovery.md:64-68`, `:247-278`, `:296-297`). That is not the detector's contract: composer visibility is classified separately from the turn-in-flight fingerprint (`src/gobby/agents/idle_detector.py:200-246`), and an active turn can display an empty or draft composer. The CAS only catches updates after observation; it does not protect a session legitimately activated after daemon start but before the delayed scan. The hook replay barrier also has unresolved/timeout branches, so merely awaiting it does not prove every session is settled (`src/gobby/runner_lifecycle_agents.py:682-787`; `src/gobby/runner_lifecycle_subsystems.py:627-628`). **Required repair:** define one shared-snapshot predicate that (a) preserves `active` whenever turn-in-flight evidence exists, (b) considers only rows at or before the captured daemon-start/restart horizon, with equality and units specified, (c) excludes every unresolved session reported by the hook barrier, and (d) retains the observed-`updated_at` CAS plus a final pre-write recheck. Add tests for empty/draft/unknown crossed with in-flight/not-in-flight, pre/equal/post-cutoff activity, a CAS race, and unresolved ordinary and agent-run sessions.

2. **BLOCKING — The committed-status listener can replay before the startup barrier it is supposed to respect.** Section 1.1 registers the listener when the dispatcher is bound to the daemon loop (`.gobby/plans/wake-delivery-recovery.md:177-183`), but owner-loop binding happens before HTTP bind and subsystem recovery (`src/gobby/runner_lifecycle.py:191`, `:259`). A transition in that window can dispatch before terminal-host adoption, hook replay, and the initial reconciliation pass required by section 2.1 (`.gobby/plans/wake-delivery-recovery.md:273-278`; `src/gobby/runner_lifecycle_subsystems.py:603-635`). Per-session coalescing prevents duplicate tasks; it is not a readiness barrier. **Required repair:** give the replay coordinator an explicit closed/open startup gate. Before readiness, callbacks may record/coalesce recipient intent but must not write. Open and drain the gate only after host adoption, a session-aware hook-barrier decision, and initial reconciliation. Test a committed `active -> paused` transition between owner-loop binding and barrier completion and prove zero terminal writes before readiness.

3. **BLOCKING — Acceptance proves scheduling, not durable delivery.** The plan tests a replay call and preservation on failure (`.gobby/plans/wake-delivery-recovery.md:192-198`, `:294-301`), but it never reproduces the required two-message, five-seconds-apart mid-turn case end to end or proves that normal context injection/receipt eventually sets `delivered_at`. It likewise lacks a restart regression that starts with a stale `active` session and a marked pending row, performs reconciliation, and reaches delivery without pane input. This leaves the central contract unproved even though replay intentionally does not acknowledge rows itself. **Required repair:** add an isolated integration acceptance item/test that sends two `wake=true` messages five seconds apart during an active turn, asserts the second send's structured decline and exactly one INFO line containing session/message/reason, commits the end boundary, observes one coalesced wake/context injection, and verifies both rows' `delivered_at`. Add the analogous post-restart path and assert no manual terminal input is needed.

4. **BLOCKING — The shared replay task has no cancellation-safe ownership contract.** The plan says concurrent callers join one task and that cancelled replay remains retryable (`.gobby/plans/wake-delivery-recovery.md:177-186`, `:194-197`), but does not state who owns the task, whether joiners are shielded, how exceptions are observed, or how map cleanup avoids deleting a newer replacement task. Directly awaiting a shared task lets one cancelled joiner cancel everyone; retaining a completed task makes later boundaries join dead work. **Required repair:** specify the smallest correct coalescer: coordinator-owned per-session tasks; joiners use `asyncio.shield`; every terminal outcome is observed/logged; cleanup removes a slot only if it still contains that exact task; later boundaries may retry without touching `delivered_at`. Test dispatch exception, owned-task cancellation, cancelled joiner, retry after each outcome, and stale cleanup racing a replacement.

5. **BLOCKING — Deliverable 2.1 combines independently closeable lifecycle owners and is not one-worker sized.** It joins restart status reconciliation/startup ordering with native Codex terminal discovery, rebinding, stale-owner cleanup, and provider-neutral wake/send-keys routing across more than ten production targets (`.gobby/plans/wake-delivery-recovery.md:208-240`, `:257-301`). Either half has a useful, independently testable outcome; their only interaction is an ordering dependency before replay. The stated reason that splitting could replay into an unbound pane is solved by an explicit dependency/readiness gate, not by one oversized commit. **Required repair:** split 2.1 into separate backend deliverables for (a) restart/session reconciliation plus startup replay readiness and (b) pre-created native resume binding plus wake/send-keys resolution. Give each its own exact acceptance and validation targets, and state the real dependency between them. As written, the plan explicitly depends on 1.1 and is not ready for a worker to implement #22654 first.

6. **BLOCKING — Passing ordered `message_ids` through every dispatcher path is unnecessary mechanism.** The plan already establishes that mailbox rows and recipients are ordered and can be correlated at the mailbox boundary (`.gobby/plans/wake-delivery-recovery.md:137-140`), yet it expands generic single/batch dispatcher signatures and every fallback to carry optional IDs (`:162-170`). No non-mailbox consumer needs that data. This creates avoidable signature churn and test-double breakage, including `tests/servers/routes/test_tasks_routes.py`. **Required repair:** keep dispatcher results limited to stable structured decline reasons. Let `mailbox_delivery` zip the committed messages, recipients, and results, attach message IDs to the sender response, and emit the one required mailbox INFO record. Only retain dispatcher-side logging for non-mailbox concerns that have an actual consumer.

7. **BLOCKING — The target and verification inventory misses direct consumers affected by the proposed seams.** The target list and pytest command (`.gobby/plans/wake-delivery-recovery.md:109-125`, `:211-233`, `:309-315`) omit wrapper consumers of `activate_materialized_session`/`handle_pre_created_session` (`src/gobby/hooks/event_handlers/_session_start/__init__.py`), reduced-runner startup coverage (`tests/test_bm25_startup.py`), existing hook-barrier/restart branches (`tests/test_runner_lifecycle_restart_replay.py`), the shared terminal store fake (`tests/terminals/fakes.py`), and the raw-tmux fallback suite (`tests/mcp_proxy/tools/sessions/test_terminal.py`). A new public SessionManager CAS would also change the exact import/API contract covered by `tests/storage/test_sessions_import.py`; if the dispatcher signature from finding 6 remains, its route fake must be updated too. **Required repair:** add these production consumers as targets or explicit `Consumers unchanged`, add every affected test to the focused pytest and quality/type audits, and prefer a private CAS seam unless a public API consumer is named.

8. **BLOCKING — The validation section contradicts task acceptance and cannot prove the live recovery criterion.** It forbids daemon restart and runs only path-scoped Ruff (`.gobby/plans/wake-delivery-recovery.md:303-318`), while #22653 requires whole-tree `uv run ruff check src/ tests/` and a post-announced-restart live check with two recorded message IDs delivered within one minute. It also checks the line threshold only for `wake.py` and `mailbox.py`, not every hand-maintained production file touched by the split deliverables. **Required repair:** retain isolated pytest for worker validation, add the exact whole-tree Ruff command, include the newly identified tests in one quality/type audit invocation, and add a separately coordinated main-checkout live validation step: announce the restart globally, wait for a quiet window, send the two messages five seconds apart, record IDs/decline/log evidence, and prove both `delivered_at` timestamps within one minute. Add an explicit under-1,000-line check for every touched hand-maintained production file and the stricter under-850 checks for `wake.py` and `mailbox.py`.

## Exact revisions required

1. Replace composer-only restart recovery with the combined in-flight, restart-horizon, unresolved-session, and CAS predicate from finding 1.
2. Add the startup-readiness gate and cancellation-safe replay-task contract from findings 2 and 4.
3. Add end-to-end mid-turn and post-restart delivery tests that finish at `delivered_at`, not merely dispatch scheduling.
4. Split section 2.1 into restart-reconciliation and native-resume-routing deliverables with explicit dependencies and worker-sized scopes.
5. Keep message correlation at the mailbox boundary unless the plan names a concrete non-mailbox consumer.
6. Complete the affected-consumer/test inventory and update the focused validation commands.
7. Add whole-tree Ruff, coordinated live restart evidence, and complete line-ceiling validation.

The no-shim decision is correct, and the direct extractions for the current 983-line `wake.py` and 910-line `mailbox.py` appropriately address the immediate monolith risk. Those points do not offset the blocking safety and proof gaps above.

**VERDICT: REVISE**
