# Wiki governance extras — design pass (strategy)

Produced by task #17522 (epic #17494). Source candidates:
`.gobby/plans/gobby-wiki-parity-research-pipeline.md` §Wiki-bakeoff findings
(llm-wiki adoption candidate C10, plus Graphify C7 and C8). This is a
`strategy` plan: narrative only, no task manifest. Implementation is owned by
a standalone backlog task created alongside this document — deliberately NOT
under epic #17494, because these extras are not required for parity or the
research pipeline.

## 1. Scope

`kind: framing`

Design each deferred governance candidate against gwiki's existing
credibility/audit/provenance/export/maintenance modules so implementation
reuses them instead of duplicating them. Verdicts below are one of:
**already shipped**, **adapt existing**, or **adopt on existing plumbing**.

Non-goals: no implementation in this pass; no changes to the parity plan's
Part A/B loops; no new storage tables; no new inline page markup formats.

## 3. Verdicts per candidate

`kind: framing`

### 3.1 C8 — Token-budget-capped query output: ALREADY SHIPPED

`kind: framing`

`gwiki search` and `gwiki ask` accept `token_budget`, wired CLI → `api.rs` →
gateway → MCP (`wiki_search`/`wiki_ask`). No remaining work. Do not file a
task.

### 3.2 C10d — Agent export surfaces: ~60% shipped; finish, don't rebuild

`kind: framing`

Already emitted by `exports/graph.rs`: `graph.jsonld`, `llms.txt`,
`llms-full.txt`. Remaining pieces, each mapped to an existing mechanism:

- **Per-page `.json` siblings**: serialize `WikiFrontmatter::as_json()` plus
  outbound links and lifecycle/confidence (below) per page. New
  `ExportCommand` variant in `exports.rs`; no new metadata model.
- **Per-folder `_context.md`**: this is an index concern, not an export
  concern — fold into `catalog.rs` regeneration (it already owns
  `_index.md`/`INDEX.md` discipline) so the token-frugal traversal files stay
  deterministic and LLM-free.
- **`ai-readme.md`**: static navigation template written once by
  `gwiki init`/`setup`, regenerated by catalog only if missing.
- **Gating**: all agent exports must exclude quarantined candidates and
  archived pages (lifecycle below). Today exports have no exclusion filter;
  add one predicate shared with retrieval.

### 3.3 C10a — 4-factor confidence score: ADAPT (compose existing signals)

`kind: framing`

Do NOT port the bakeoff formula (`sources*0.3 + quality*0.3 + recency*0.2 +
xrefs*0.2`) as a parallel scorer — three of its four factors already exist as
signals:

- *sources* + *quality*: aggregate the existing per-source
  `CredibilityScore` over a page's cited sources (via `ProvenanceGraph`
  links / manifest backing).
- *recency*: reuse the freshness-signal curve, parameterized with a
  content-type half-life (Ebbinghaus decay): map page `tags`/section to a
  half-life (e.g. bug facts 14d, architecture 180d) instead of the current
  single window. This extends `credibility.rs::freshness_signal`, not a new
  module.
- *xrefs*: backlink count from the existing link graph
  (`links.rs`/`graph/`), already computed for lint/catalog.

Ship as a **derived, recomputed** page-level `CredibilityScore` composition in
`credibility.rs`, surfaced through `gwiki health`/`gwiki trust` reporting and
written into export surfaces (per-page `.json`, `graph.jsonld` node
attributes). Do not persist it in page frontmatter as a source of truth — it
drifts; recompute on health/upkeep runs. Exact weights are a tuning decision
deferred until Part A loops produce real distributions; the design only fixes
the composition points.

### 3.4 C10b — 5-state page lifecycle: ADAPT (formalize what exists)

`kind: framing`

gwiki already has an implicit lifecycle: compile writes pages, lint/librarian
review them, audit verifies citations, `mark_stale_markdown` + health mark
staleness. Missing: a single named state and an `archived` terminal.

- One new frontmatter key `lifecycle: draft | reviewed | verified | stale |
  archived` on `WikiFrontmatter` (typed field, not `unknown` passthrough).
- Transitions are owned by the loops that already exist — compile/upkeep
  create at `draft`; lint+librarian clean pass promotes to `reviewed`; audit
  citation pass promotes to `verified`; health demotes to `stale` via the
  existing `mark_stale_markdown` path (keep its `reason`); upkeep archives
  long-stale or superseded pages (`archived` = excluded from catalog indexes,
  agent exports, and default retrieval; file stays in place — no move, the
  wiki branch publisher and SourceManifest must keep seeing stable paths).
- Every transition appends a `log.md` entry (append hook already wired by
  parity Part A step 3). That is the audit trail; no new table.
- `trust` remains an orthogonal reporting axis (evidence quality), lifecycle
  is workflow state; do not merge them.

### 3.5 C10c — Candidate quarantine: ADOPT on existing plumbing

`kind: framing`

LLM-proposed entity/concept pages start untrusted:

- Quarantine = `lifecycle: draft` + `candidate: true` frontmatter (typed
  field). No separate directory — moving files would churn links, the
  publisher, and SourceManifest paths.
- Default-excluded from agent exports and `wiki_ask` retrieval via the same
  shared exclusion predicate as `archived` (retrieval keeps an opt-in
  `include_candidates` flag for the librarian/upkeep loops themselves).
- **Promotion**: upkeep already gates concept creation on clustered
  unresolved-link `mention_count >= 2`; promotion clears `candidate` when a
  candidate accrues corroboration (backlinks ≥ threshold or audit pass).
  **Merge**: existing near-dup path (Qdrant ≥ 0.90 update-over-create)
  resolves a candidate into an existing page. **Discard**: existing
  `gwiki purge` + a `log.md` entry.
- Audit trail = `log.md` entries for propose/promote/merge/discard, same as
  lifecycle transitions.

### 3.6 C7 — Per-claim EXTRACTED|INFERRED|AMBIGUOUS labels: MAP, don't add markup

`kind: framing`

The accepted-note contract and audit already carry the distinction:

- EXTRACTED ≈ claim backed by a `citation:` line / provenance-graph link.
- INFERRED ≈ synthesized claim that is grounded (manifest-backed page) but
  has no direct per-claim citation.
- AMBIGUOUS ≈ claim in `conflict:` / `gap:` territory.

Implement as a classification dimension in `audit/claims.rs` output (and the
per-page `.json` export), NOT as new inline page markers — consistent with
the parity plan's decision to keep digest prose free of self-referential
markers. Readers get the label from audit reports and agent exports; page
bodies stay clean.

## 4. Sequencing and dependencies

`kind: framing`

All implementation is post-merge of `task-17495` and gated on the parity
plan's Part A loops (upkeep, audit exemptions, catalog, log wiring) running in
production — confidence tuning and stale/archive thresholds need real
distributions from those loops.

Dependency order inside the successor task:

1. **Lifecycle field + shared exclusion predicate** (foundation; touches
   `frontmatter.rs`, `health.rs`, `upkeep.rs`, catalog/export/retrieval
   filters).
2. **Candidate quarantine** (depends on 1; touches `upkeep.rs`, retrieval,
   purge, log).
3. **Page-level confidence composition** (depends on Part A data; touches
   `credibility.rs`, `health.rs`/`trust.rs`, feeds lifecycle
   stale/archive decisions).
4. **Export completion** (per-page `.json` + `_context.md` via catalog +
   `ai-readme.md`; consumes 1–3's fields).
5. **C7 audit classification** (independent of 1–4; can land anytime after
   the Part A audit changes).

C8 requires no work. Each step is small enough to be one leaf task when the
successor backlog task is expanded; expansion should happen only when the
work is actually scheduled, against the then-current code.
