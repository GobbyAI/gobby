# Restore Operator-Launched Panes And CLI Sessions After A Reboot

## Overview
`kind: framing`

Task #24763 (Restore operator-launched panes and CLI sessions after a reboot), under
epic #24821 (Terminal and client). Planning task #25414. A machine reboot kills the gterm
host and every process in it. Today the daemon then forgets the operator's work:

1. Startup reconciliation marks each prior-epoch terminal `orphaned`, and the next
   health-loop pass marks it `exited`
   (`src/gobby/terminals/host_reconcile.py:383-389`).
2. The first workspace read sweeps every pane whose terminal is `exited` and drops tabs
   left empty (`src/gobby/storage/workspaces.py:889-955`). The committed RED test
   `tests/terminals/test_reboot_pane_preservation.py` (`f2b6df2d63`) fails 2 of 6 on
   `0.5.0` for exactly this reason.
3. Nothing relaunches an operator's shell or the provider CLI the operator typed into
   it, and nothing records where that shell ran.
4. A session that was mid-turn at the reboot expires as ownerless with no drain marker
   (`src/gobby/storage/sessions/_field_update.py:261-297`), so its task claims are
   released as if the operator had closed it.
5. Task-owned managed seats parked by the daemon stop are never relaunched; they wait
   24 hours for the reaper, which releases their claims.

The plan delivers:

1. Durable facts: the terminal's process record keeps its spawn folder and a
   `host_lost` flag set when the host loses it.
2. Panes whose terminal the host lost survive the sweep until restored or closed.
3. At daemon start, each operator pane gets a new shell in the same pane row. If its
   provider session can resume natively, the shell runs the provider's resume
   command. Otherwise it prints one line naming the reason and the exact resume
   command. A pane whose CLI had already ended before the reboot comes back as the
   plain shell it was.
4. Managed seats refill their own pane in place, and parked task-owned seats are
   relaunched.
5. gclient draws a pane with no live terminal as an explained pane instead of a blank
   slot.

## Decision Record
`kind: framing`

1. **Retained history is the session and transcript (Option A).** Orchestrator
   ruling (gobby#17281, 2026-10-31) on the Plan Writer's request: the session row and
   its transcript are never deleted or archived. A restored pane that cannot resume
   prints one line naming the reason and the exact resume command. Gterm scrollback is
   not persisted across a reboot. Option B (on-disk gterm scrollback snapshots) was
   rejected: it adds a large Rust persistence layer and writes terminal text, which can
   hold secrets, to disk. `gterm-handover.json` survives only exec upgrades, not a
   reboot (`crates/gterminal/src/host/handover.rs`). Josh approves the stamped plan before
   expansion.
2. **Host loss is a flag on the terminal's process record.**
   `TerminalSettlementMixin.mark_orphaned` (`src/gobby/storage/terminal_settlement.py:428-430`)
   is the only `live` to `orphaned` writer, and its docstring scopes it to host-epoch or
   host-crash loss. It merges `{"host_lost": true}` into `terminals.process`. Key merges
   (`merge_process_reap_record`, `record_orphan_identity`) keep keys outside
   `HOST_PROCESS_KEYS`, so the flag survives `orphaned` to `exited`. `mark_kill_failed`
   also writes `orphaned` but is not host loss, so it sets no flag. Rejected: a new
   `terminals` column, which needs a migration, five derived schema carriers and crate
   bumps for one boolean. Also rejected: comparing host epochs alone, which cannot tell a
   shell the operator exited before the reboot from one the reboot killed.
3. **The spawn folder is recorded in the same process record.** `spawn_web_terminal`
   (`src/gobby/terminals/web_spawn.py:186-197`) already writes
   `{host_terminal_id, shell, pgid, start_time}`; it adds `cwd`. A pane keeps pointing
   at its last terminal until it is rebound, so that terminal row is the pane's
   last spawn folder. Rejected: a `workspace_panes.cwd` migration, for the same carrier
   cost. Also rejected: deriving the folder from the tab's project and worktree, because
   operator personal-project panes carry an explicit folder stored nowhere else
   (`src/gobby/terminals/workspace_pane_access.py:69-117`).
4. **Operator panes restore through a new sibling path, not managed resume.**
   `launch_resume` and its `_preflight` (`src/gobby/agents/resume_placement.py:77-236`)
   require a pane reserver, a managed SRT sandbox and a parent session.
   `prepare_terminal_resume(relaunch=True)` overwrites `parent_session_id`, which would
   turn a root into a child. Roots stay roots: the new module
   `src/gobby/terminals/pane_restore.py` spawns into the existing pane row.
5. **Which provider sessions resume.** A reboot leaves the pane's last terminal row
   bound to its session. `TerminalManager.release_session`
   (`src/gobby/storage/terminals.py:756-772`) unbinds only a `pending` or `live` row,
   on `SessionEnd` (`src/gobby/hooks/event_handlers/_session_end.py:256`) or a liveness
   expiry (`src/gobby/sessions/liveness_monitor.py:437`), and the reboot leaves the row
   `orphaned`. A CLI ended before the reboot was unbound then. Its pane was already a
   plain shell, so it restores as one, with no line. Rejected: looking up the pane's
   last session through `terminal_context` to explain it, which adds a lookup for a
   pane the operator had already returned to a shell. The bound session resumes only
   when all of these hold:
   - its `agent_run_id` is null;
   - its source is in `SUPPORTED_RESUME_PROVIDERS`
     (`src/gobby/agents/resume_executor.py:79`);
   - it has a native thread id (the rule in `resolve_resume_target`,
     `src/gobby/mcp_proxy/tools/spawn_agent/_resume.py:58-113`);
   - its status is in `LIVE_SESSION_STATUSES`, or it is `expired` carrying the
     `terminal_drain` contested-expiry marker;
   - no `pending` or `live` terminal is bound to it.

   A `SessionEnd` expiry writes no marker (`src/gobby/hooks/event_handlers/_session_end.py:86-108`),
   so a deliberately ended session that is still bound stays closed and its pane prints
   the reason line. The exception is a `SessionEnd` caused by the host's death (item 9).
   `completed`, `cancelled`, `closed` and `deleted` stay closed. The 24-hour revival horizon clears session variables, marker
   included, so a stale seat stays closed.
6. **The restore command is one `zsh -i -c` script.** The pane's shell is
   `PANE_SHELL_COMMAND = ("zsh",)` (`src/gobby/terminals/workspace_ops.py:85`). The
   restored command is `("zsh", "-i", "-c", script)`, where the script is
   `cd <folder> && <resume argv>` or `printf '%s\n' <reason line>`, then
   `; exec zsh -i`. Every value is quoted with `shlex.quote`, argv with `shlex.join`.
   `-i` sources the operator's `.zshrc`, so the provider binary resolves on the
   operator's own PATH, and the pane ends in an ordinary interactive shell. Rejected:
   typing the command into a fresh shell's PTY, which has no prompt-ready signal and
   races typeahead handling.
7. **Provider argv comes from `build_cli_command` with auto-approve off.**
   `src/gobby/agents/spawners/command_builder.py::build_cli_command` with
   `resume_session_id=<thread>`, `model` and `reasoning_effort` from the session,
   `auto_approve=False`, no prompt, no working directory, and a fixed mode per provider:
   claude `agent` (`claude --resume <id>`; `interactive` would add stream-json I/O),
   codex `agent` (`codex resume … <id>`), grok `terminal` (`--resume <id>` without
   `--single`), droid `interactive` (`droid --resume <id>`), agy `interactive`
   (`agy --conversation <id>`). The env dict it returns is discarded. The restored shell
   gets only the pane identity env.
8. **Managed seats refill their own pane in place.** A new placement kind,
   `{"pane": {"pane": <pane id>, "title": <title>}}`, binds a new terminal into an
   existing pane whose terminal is proven dead (item 13). Both managed resume routes
   use it first when the previous run's pane still exists: `_preflight` for automatic
   daemon-stop recovery and `resumed_seat_plan` for `spawn_agent(resume_session_id=…)`.
   Rejected: today's split beside the dead pane, which relies on the sweep to collapse
   the old pane. It changes the pane id, and once the sweep keeps host-lost panes it
   would leave a ghost pane beside the successor.
9. **Sessions active at the reboot are shielded like paused ones.** When the
   session's bound native terminal carries `host_lost`, `expire_if_active` records the
   `terminal_drain` marker in the same transaction as the expiry. This is the guarantee
   `expire_if_paused_terminal_exited` already gives paused sessions (`_field_update.py:299-370`).
   `rebind_resumed_terminal_session` (`src/gobby/storage/sessions/_terminal.py:217-288`)
   sets the session `active` with direct SQL and skips `update_status`'s rule that a
   status change clears the marker (`_field_update.py:62-80`). It now clears it too, so
   a resumed seat's marker cannot shield a later final expiry. A provider may fire
   `SessionEnd` when its host dies. Codex installs it enqueue-only. On a drain, HTTP
   admission closes (`src/gobby/runner_lifecycle_shutdown.py:724`) before the host stops
   (741-750), so the hook lands in the inbox the way it does on a reboot. The inbox
   replays it after the restart, inside `agent_run_reconciliation`
   (`src/gobby/runner_lifecycle_reconcile.py:431-445`), after host reconcile has set
   `host_lost`. A `SessionEnd` expiry therefore gets the same rule only for the generic
   reasons `other` and `exit` (Grok's `shutdown` maps to `exit`,
   `src/gobby/hooks/hook_types/enums.py:155-191`). `prompt_input_exit`, `logout`,
   `clear`, `resume` and `idle` are explicit closes and stay closed through replay.
   The operator ruled that `exit` stays in the generic set (V1).
10. **Parked task-owned seats are relaunched by the existing retry loop.** The query
    behind `_retry_parked_non_task_resumes` (`src/gobby/runner_lifecycle_agents.py:340-401`)
    admits `task_id IS NULL` only. The comment that task-owned runs "ride the dispatch
    tick" is stale: fe8e05f7c7 (#23851) retired the dispatcher, leaving
    `list_daemon_stop_resume_candidates` (`src/gobby/storage/agents/_queries.py:114-146`)
    with no production caller. The candidate query now also admits task-owned runs
    whose task is not closed. A run whose task is closed is refused with
    `refuse_parked_daemon_resume` (`src/gobby/storage/agent_resume.py:79-125`), which
    hands it to the reaper. A Dev Manager's manual resume and the automatic retry
    cannot both win, because consuming a parked run takes the resume fence
    (`_lock_resume_fence`, `agent_resume.py:68-72`). The dead query is deleted.
11. **Restore runs once per daemon start.** It is a startup phase, `pane_restore`, in
    `_recover_after_restart` (`src/gobby/runner_lifecycle_subsystems.py:643-757`),
    after `agent_run_reconciliation`. It is machine-local, so it also runs in node mode.
    A gterm host crash while the daemon stays up is not restored until the next daemon
    start. Its panes stay, explained, until then or until the operator closes them.
12. **gclient explains a slot with no live terminal.** `render_panes`
    (`crates/gclient/src/ui/panes.rs:73-173`) skips a layout slot whose terminal it
    cannot resolve, leaving it blank. It now draws a one-line note there. Rejected:
    keeping exited terminals attached in the client, which would change the client's
    terminal lifecycle for every exit, not just host loss.
13. **A pane is refilled only when its terminal is proven dead, under an exclusive
    claim.** `orphaned` is unresolved ownership. `mark_kill_failed`
    (`src/gobby/storage/terminal_settlement.py:375-426`) writes it after an unproven
    kill, and `handle_host_death` (`src/gobby/terminals/host_manager.py:476-496`) writes
    it with `host_lost` in the current host epoch. The proof is the one reconcile
    already settles on (`src/gobby/terminals/host_reconcile.py:385-390`): `exited`, or
    `orphaned` from a host epoch other than the live one with
    `recorded_process_group_is_alive` false. A refill claims the pane in one transaction.
    `WorkspaceManager._guard` (`src/gobby/storage/workspaces.py:957-986`) locks the pane
    row, refuses an in-flight pane or an in-doubt terminal, and checks that the pane
    still points at the old terminal. The pane is then marked in flight. The bind
    updates the pane only while it still points at that old terminal. Operator restore
    and managed refill share these rules.

## Granularity
`kind: framing`

Nine deliverables in four phases. The settlement flag and spawn folder (1.1) are
facts written at different times, but both live in one record and are tested
together. The sweep (1.2) and the session marker (1.3) are separate lifecycle owners
with separate tests. Operator restore (2.1), managed in-place placement (2.2) and the
parked task-seat retry (2.3) are three owners: the new restore module, the pane
reserver, and the lifecycle monitor's retry loop. 1.2 holds the sweep's keep rule and
the refill claim together because both are storage rules over the same pane and
terminal rows, and 2.1 and 2.2 consume both. 2.1 exceeds six acceptance items
because eligibility, command shape, folder fallback, idempotence, secrets, rollback,
death proof and failure isolation are separate faults in one restore lifecycle. Splitting it would ship a
restore that can duplicate a process or leak env in between. The reboot regression
suite (4.1) is its own deliverable because it crosses 2.1, 2.2 and 2.3. The gclient
leg (3.1) and the docs (3.2) follow behavior.

### 1.2 Keep host-lost panes and guard their refill [category: code] (depends: 1.1)
`kind: deliverable`

Targets:
- `src/gobby/storage/workspace_pane_recovery.py`
- `src/gobby/storage/workspaces.py::WorkspaceManager.sweep_dead_panes`
- `tests/terminals/test_reboot_pane_preservation.py::*` — scope-reason: turns the committed RED sweep case green without changing its assertions
- `tests/storage/test_workspaces.py::*` — scope-reason: adds the ordinary-exit and settled-managed sweep cases

Research context. `sweep_dead_panes` (`workspaces.py:889-955`) runs two queries: the
candidate `SELECT` (`term.state IS NULL OR term.state NOT IN ('pending', 'live', 'orphaned')`)
and the re-checking `DELETE … NOT EXISTS (… term.state IN ('pending', 'live', 'orphaned'))`.
The sweep runs on read: `WorkspaceOps._sweep_storage` (`workspace_ops.py:687-689`) via
`workspace_snapshot` (236-347), and `registry.py:187` and `workspace_ws.py:249`. The new
module defines `keep_pane_terminal_sql(db) -> str`. It returns one SQL boolean over
alias `term` that holds when:
- `term.state IN ('pending', 'live', 'orphaned')`; or
- `term.state = 'exited'` and `COALESCE((term.process->>'host_lost')::boolean, false)`,
  and either `term.agent_run_id IS NULL`, or an `agent_runs ar` row for it is still
  recoverable. Recoverable means `ar.status` is in `ACTIVE_AGENT_RUN_STATUSES`
  (`src/gobby/storage/agents/_constants.py:42-46`), or it is
  `ar.status = 'cancelled' AND ar.terminal_reason = 'daemon_stop'` passing
  `daemon_resume_unconsumed_condition` and `daemon_resume_not_reaping_condition`
  (`src/gobby/storage/daemon_resume_keys.py:33-51`, column `ar.resume_metadata_json`).

Both queries call it in place: the candidate filter becomes
`AND NOT COALESCE((<keep>), false)` and the `DELETE` re-check
`AND <keep>`. The docstring is rewritten within its existing lines, so the file
grows by the import line only (996 to 997). A managed pane whose run was
refused, reaped, torn down or ended normally is swept as today. An operator pane
stays until 2.1 rebinds it or the operator closes it. `remove_pane`
(`workspaces.py:691-705`) still hard-deletes on explicit close.

The same module holds the refill claim (Decision Record item 13), which 2.1 and 2.2
use. `claim_pane_refill(workspaces, pane_id, *, old_terminal_id) -> None` opens
`workspaces.db.transaction()` and calls `workspaces._guard(conn,
"p.id = ANY(%s::uuid[])", [pane_id], True, {pane_id: old_terminal_id})`
(`workspaces.py:957-986`). That locks the pane row and raises `WorkspaceBusyError` when
the pane is in flight, its terminal is held in-doubt, or it no longer points at
`old_terminal_id`. It then calls `workspaces.mark_spawn_in_flight(pane_id)` inside the
transaction, so a second claimer that waits on the row lock sees the mark.
`bind_refilled_pane(db, pane_id, *, old_terminal_id, new_terminal_id) -> WorkspacePane | None`
runs `UPDATE workspace_panes SET terminal_id = %s, owns_terminal = true,
updated_at = now() WHERE id = %s AND terminal_id = %s RETURNING *`. It returns None when
the pane is gone or rebound. Only the caller that claimed the pane clears its mark,
with `clear_spawn_in_flight` in its `finally`. Guarded closes and moves already refuse
an in-flight pane, so the operator cannot close a pane mid-refill.

Move: the keep predicate and the refill claim are new logic that lives in
`src/gobby/storage/workspace_pane_recovery.py`, not in
`src/gobby/storage/workspaces.py`, which gains only the import line.
