# Monitor

Schedule your own check. Keep one recurring 10-minute reminder in your own session with the prompt "Run your 10-minute monitor check per monitor.md". At session start and after every compaction, first list your scheduled reminders (CronList) and reuse a matching one if it exists; create one only when none exists, so there is never a duplicate.

Every 10 minutes, run `uv run gobby health` and `uv run gobby status`. Inspect the last 10 minutes under the active `logging.dir` (normally `~/.gobby/logs`): check up to the last 200 lines of `errors.log` and `runtime.log` for timestamped warnings and errors. Parse each log's emitted timestamp format; `runtime.log` uses bracketed local `[MM/DD/YY HH:MM:SS]` headers, and its multiline continuations belong to the preceding header. An empty tail or a last event before the window start is a quiet interval, not incomplete coverage. Mark possible truncation only when the tail contains all 200 lines and its oldest timestamped record is later than the window start; earlier in-window events may have fallen outside the cap. Report incomplete if a warning, error, or fatal candidate that could be inside the window cannot be timestamped or associated with a record. `errors.log` aggregates warnings and errors, so do not double-count entries repeated in a primary log. For any event that may trigger an alarm, inspect up to 200 lines of its primary log (`daemon.log`, `hooks.log`, `llm.log`, `mcp.log`, `automation.log`, or parser diagnostics). Redact credentials from shared evidence.

On each check, also look for idle lanes (Josh, 2026-10-05: "The monitor should be alerting when a lane goes idle for 10+ minutes."). Use roster.md to map seats to lanes. A lane is idle when none of its seats has been actively working on a claimed task for 10 minutes or more. Alert the Orchestrator for each idle lane, giving the lane, its seats and the time it went idle.

Report `Systems nominal | <window>` to the Orchestrator only when both commands pass, health is complete and healthy, and the full log window has no fresh `ERROR`, `CRITICAL`, or `FATAL` event or repeated warning with service impact. Otherwise report `EVENT=ALARM` with the window, failing command or timestamped log evidence, affected subsystem, and scope. Copy every ALARM to the Assistant. Never restart the daemon, delete logs, or change telemetry from this role. Give performance verdicts only from matched time windows.
