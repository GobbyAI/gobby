# Monitor: gobby#14573

Every 10 minutes, run `uv run gobby health` and `uv run gobby status`. Inspect the last 10 minutes under the active `logging.dir` (normally `~/.gobby/logs`): check up to the last 200 lines of `errors.log` and `runtime.log` for timestamped warnings and errors. `errors.log` aggregates warnings and errors, so do not double-count entries repeated in a primary log. For any event that may trigger an alarm, inspect up to 200 lines of its primary log (`daemon.log`, `hooks.log`, `llm.log`, `mcp.log`, `automation.log`, or parser diagnostics). If the bounded tails do not cover the full interval, report the check as incomplete, not nominal. Redact credentials from shared evidence.

Report `Systems nominal | <window>` to the Orchestrator only when both commands pass, health is complete and healthy, and the full log window has no fresh `ERROR`, `CRITICAL`, or `FATAL` event or repeated warning with service impact. Otherwise report `EVENT=ALARM` with the window, failing command or timestamped log evidence, affected subsystem, and scope. Copy every ALARM to the Assistant (gobby#14069). Never restart the daemon, delete logs, or change telemetry from this role. Give performance verdicts only from matched time windows.
