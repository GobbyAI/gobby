Remove the hack, save the annotation durably, and validate a documented, user-initiated handoff for the specific Safari/iOS versions before shipping. [Apple DTS](https://developer.apple.com/forums/thread/764570)

2. No. Prefer `activeTab` or narrowly scoped/optional host access; justify `<all_urls>` only if functionality requires it. Concurrently overwriting one JSON queue risks lost updates. Use a transactional queue, such as SQLite in the App Group, with unique job IDs and explicit acknowledgments; test concurrent writes and interrupted processing. [Safari permissions](https://developer.apple.com/documentation/safariservices/managing-safari-web-extension-permissions), [shared-data coordination](https://developer.apple.com/library/archive/technotes/tn2408/_index.html)

3. No. iOS extensions cannot rely on persistent background JavaScript, and “done” must mean confirmed completion. Persist the export and job state, then use an appropriately configured native background `URLSession` file upload, including the shared-container configuration when initiated by an extension. Make retries idempotent and verify termination/relaunch recovery on a device. [Background persistence](https://developer.apple.com/documentation/webkit/wkwebextension/haspersistentbackgroundcontent), [background transfers](https://developer.apple.com/documentation/foundation/downloading-files-in-the-background), [shared container](https://developer.apple.com/documentation/foundation/urlsessionconfiguration/sharedcontaineridentifier)
