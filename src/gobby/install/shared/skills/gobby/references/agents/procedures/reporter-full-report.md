# reporter full report procedures

Load with the reporter procedures for a full report or a launch that requests a roster.

## Workspace seat roster
Gather the roster before supplementary full-report evidence. The full-report scaffold always includes Workspace seat roster, even when its source is unavailable. A roster-only launch gathers and delivers this section directly within the same budget and delivery contract.
Read workspace and session inventories to completion, including offloaded result pages, before asserting coverage. For offloaded get_session details, use `gobby-results:search_tool_result` to retrieve terminal_context, source, model, reasoning_effort, status and current activity metadata only; never read session summaries, handoffs or transcripts for the roster. Missing metadata remains a source gap.
Include a complete workspace seat roster in every full report and whenever the launch prompt requests a roster. Resolve your project_id and machine_id from `gobby-sessions:get_session` for your injected session ref. Lease `gobby-workspaces:list_workspaces`, select the workspace whose default_project_id matches that project on that machine, then call `gobby-workspaces:get_workspace(workspace=<selected id>, node=<machine id>)`. Never assume the projectless workspace named default is the project's default workspace. If it is missing or inaccessible, retain the roster heading with a specific source gap; never create a workspace.
List every tab in tab order, using the returned tab position, and every pane under its tab in layout order. Join panes to live sessions by matching pane terminal_id to `gobby-sessions:get_session` terminal_context.gobby_terminal_id. Reuse session refs from the complete `gobby-agents:list_running_agents` snapshot; also lease `gobby-sessions:list_sessions` for the workspace machine with limit=500 to discover interactive seats absent from agent runs. Fetch get_session for each relevant session and cache it. Do not treat session ids, run ids or labels as terminal ids. Ignore expired and archived sessions. If multiple live sessions match a terminal, report the ambiguity rather than choosing a seat. If the session inventory reaches its limit or any required source is unread, mark coverage incomplete; an unmatched pane is unknown until the live session inventory is complete.
For each pane, print its pane label (or unlabeled) and seat label/role, provider, model, reasoning effort, state, and every current claimed task ref with title (or none). Use live agent rows for role, state and current claims; use session source, model and reasoning_effort for missing provider/model/effort, never launch defaults. Resolve interactive claims from the already gathered current task rows by owner session. Missing metadata stays unknown with its source gap. A claim alone does not prove the seat is working. State is stalled when stall_suspected is true, otherwise waiting when a wait is recorded, working when current activity proves it, or idle when inactivity is recorded; retain unknown if the sources cannot distinguish them. A pane with no live session is empty, with state no seat, provider/model/effort none and task none. A live unclaimed seat retains its observed state and says task none.
Format one tab heading followed by one line per pane: `label | seat | provider / model / reasoning effort | state | task ref and title or none`. Explicit examples: `unlabeled | empty | none / none / none | no seat | task none`; `seat label | role | provider / model / reasoning effort | idle | task none`. Never omit empty panes or unclaimed seats. Report tabs_read/total and panes_read/total; delivery success does not establish roster completeness. Targeted roster session lookups and their result pages are exempt from the 35-call cap, but remain within the gathering time budget. Reuse the snapshot across report sections. Include roster_complete and roster coverage counts in the run result.

## Full report
Start with the report mode, timestamp, and evidence age. Use compact markdown blocks readable on the configured channel:
- Policy-defined roots: one block for every root, including idle or unstaffed roots. Name the epic ref and title; current task(s) ref and title, developer/reviewer seat, and time claimed; the next five queued task refs and titles in Archivist order (or all if fewer); and candidates waiting on landing/activation/close. State missing queue or claim-time evidence explicitly. Use this policy-derived scaffold when available; otherwise read every root from injected policy, and mark missing policy as a source gap:
- Close backlog: candidates sent and still open, versus the cap in the live project operating policy. A candidate still awaiting activation or close counts; exclude planning and tasks parked on an operator decision. Deduplicate task refs.
- Hold state: restart/cutover and quiet hours (the window defined by the injected project policy). Omit load numbers unless the cited evidence shows a breach.
- Blocked or escalated: task ref and title, reason, owner, and duration.
- Operator decisions: one line per outstanding open task decision, task ref and title, opened time and age, and its existing decision link if available. Report only; never ask again or create buttons.
- Stalled or idle: seat, root, claimed task ref and title if any, and duration from the last activity timestamp. Mark missing timestamps unknown.
- Worktrees: active worktrees versus developers, including mismatches from the snapshot.
- Workspace seat roster: every tab and pane, including empty panes and unclaimed seats, as specified above.
- Consolidator: last review time and source age.
- ROADMAP: stage progress from task state, plus policy-designated critical paths and their blocked dependency refs and titles.
- Last 30 minutes: landed, activated, closed, and escalated, separately, with task refs and titles and evidence timestamps. Include stuck items and alarms with their source.
