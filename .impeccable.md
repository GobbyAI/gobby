# Impeccable — Gobby Design Context

This file is the source of truth for design work on Gobby. It is read by the
`impeccable` skill before any design task. Update it via
`impeccable teach` rather than editing freely.

This contract spans every Gobby surface — current and future:

- **Product UI** (`./web/`, React/Vite) — the daily driver. In-place
  modernization toward this contract via the ongoing Tailwind 4 migration.
- **gobby.ai marketing site** — greenfield rebuild against this contract.
  Same tokens and voice as the product UI; editorial weight permitted.
- **Gobby Pro** — cross-machine fleet management UI (future).
- **Installer / setup wizard** — the first impression for new users.
- **CLI / TUI surfaces** — type, voice, and color tokens propagate where
  the medium allows.

All surfaces share one design system. They diverge on density, motion
budget, and default theme — see "Surfaces" below.

---

## Design Context

### Users

**Primary today:** developers who already live in AI coding CLIs — Claude
Code, Gemini CLI, Codex, Factory Droid. They run a local daemon, edit YAML
workflows by hand, and read logs without flinching. Power users with strong
keyboard muscle memory and high tolerance for density.

**Adjacent / near-future:** technically inclined non-developers who want a
"control plane for AI agents" in the OpenWebUI / Hermes mold. Comfortable
with command palettes and JSON; not necessarily writing Python.

**Future (Gobby Pro):** operators managing fleets of machines running Gobby —
cross-machine sync, multi-host dashboards, team-shared sessions. The UI must
scale from one daemon to N without redesign.

**Usage context:** daily driver. Open on a second monitor, glanceable from
across the room. Gobby also runs autonomously while the user sleeps, so the
interface must communicate state at low attention without losing depth on
demand. This is a "calm but dense" product, not a "splash and dazzle" one.

### Brand Personality

**Three words:** industrial, efficient, slick.

The Gobby brand is a small green goblin in round glasses holding a tablet,
surrounded by a network halo. That's the duality: a serious daemon doing
heavy work, with a streak of mischief. The UI should lean hard into the
serious side — the goblin is the mascot, not the aesthetic.

**Tone:** technical, direct, opinionated. Speaks the way a senior engineer
talks to peers — no marketing fluff, no over-explanation. Mistakes are
named, not euphemised.

**Emotional goal:** confidence and calm. The user is trusting Gobby with
agents that run unattended. The UI should make them feel like the system is
in control, not improvising.

### Aesthetic Direction

**Reference set (what to study):**

- **Vercel** — primary reference. High-contrast monochrome, Geist-class
  typography, generous negative space, blacks that are actually black,
  asymmetric grids, sharp single accents. Industrial precision.
- **Linear** — tight type hierarchy, exponential motion, restrained color,
  product-density done right.
- **Notion** — humane warmth and page-like calm without over-decoration.
- **Ghostty** — terminal-grade typographic care, monospace done as a craft
  not a costume.
- **Perplexity** — editorial information density.
- **Apple liquid glass** — material depth, frosted layering, light bending
  as a substitute for chrome.

**Synthesis:** materials over decoration. Sharp typography, real glass-like
depth where it earns its place, restraint everywhere else.

- No glassmorphism slapped on cards as a tell.
- Avoid gradient-text headlines.
- Keep status indicators subtle rather than using border-left stripes.

**Anti-references (what to actively avoid):**

- Generic "AI dashboard" template — neon cyan-on-dark with purple gradients
  and floating cards, the 2024-2025 monoculture
- Material Design 3 baseline as a destination
- Heavy use of icons-with-rounded-squares above every heading
- Hero-metric-card layouts (big number, small label, sparkline accent) as a
  default for every dashboard
- Anything that looks like a Tailwind UI starter kit untouched

**Theme:** dark by default in the product UI, light treated as a
first-class peer. Equal polish, equal review effort, no second-class
treatment. Theme choice is derived from "always-on second monitor in a dim
room" (dark wins) but acknowledged for users with bright environments and
accessibility needs.

### Surfaces

All Gobby surfaces share the same design system. They diverge in how
densely they pack content, how much motion they're allowed, and which
theme they default to.

**Shared across every surface (the "system"):**

- Color tokens (brand accent at hue 125, neutral ramp tinted toward
  brand, state palette)
- Typography stack (body + mono pairing, type scale, weight ladder)
- Voice — direct, technical, no marketing fluff regardless of medium
- Motion language (exponential easing, no bounce, reduced-motion respected)
- Iconography
- The Gobby mascot — used sparingly, never as decoration

**Product UI (`./web/`)**

- Density: high. Power users dive in deep daily.
- Motion: minimal. Functional only — entrances, state changes, feedback.
  No scroll-triggered theatrics.
- Theme default: dark.
- Reference set primary: Vercel Dashboard, Linear, Ghostty.
- **In-place modernization, not greenfield.** The current React/Vite
  app evolves toward this contract via the ongoing Tailwind 4 migration.
  No parallel rebuild — every PR moves a component closer to the system,
  legacy CSS files are retired as their consumers migrate.

**gobby.ai marketing site (greenfield rebuild)**

- Density: low to medium. Editorial. Hero moments earn their pixels.
- Motion: meaningful but restrained. Scroll-driven reveals are allowed
  *if* they reinforce the narrative, not as filler.
- Theme default: open. Pick what serves the narrative — likely dark hero
  with light editorial sections, or vice versa. The point is intentional
  contrast between sections, not a single locked palette.
- Reference set primary: Vercel marketing, Linear marketing,
  Ghostty.org, Apple product pages.
- The marketing site sells "interactive when you need it, autonomous and
  deterministic when you don't." The visual rhythm should embody that —
  periods of stillness, then sharp inflection. Not a continuous swirl of
  motion.
- Performance budget: LCP under 1.5s on 4G, no blocking JS for
  above-the-fold content. Marketing pages load like documents, not
  applications.
- **This is the greenfield surface.** Built from scratch against this
  contract, with no legacy CSS or component baggage to inherit. The
  product UI's design system is the input; the marketing site's job is
  to prove the system can carry editorial weight without losing its
  industrial precision. A display font (TBD) is permitted here; the
  product UI body + mono pairing remains the floor.

**Gobby Pro**

- Density: highest. Multi-machine dashboards, fleet roll-ups.
- Motion: minimal. Same rules as product UI.
- Theme default: dark, with operator-friendly contrast.
- Inherits the product-UI design language wholesale; extends with
  multi-host primitives (machine cards, sync state indicators, role-based
  surfaces).

**Installer / setup wizard**

- Density: low. One decision per screen.
- Motion: gentle. State transitions and progress only.
- Theme default: follow OS preference.
- This is the first impression — restraint is the message.

**CLI / TUI**

- Color tokens map to ANSI/24-bit equivalents that survive deutan-safe
  constraints (state palette by lightness primarily, hue secondarily).
- Voice rules apply verbatim. No emoji in error output, no exclamation
  points, no "✨ done!".

### Color Constraints (HARD)

The user (and primary developer) is **deutan colorblind** (red/green
deficiency). This is not a nice-to-have accommodation — it shapes the
palette. The Gobby logo is a saturated green; brand color and state color
are strictly separated.

The palette below is the locked, shipped system. It lives in
`web/src/styles/index.css`. Any new surface inherits these tokens.

**Brand accent (hue 125, chartreuse / yellow-green):**

| Token | Dark | Light |
|---|---|---|
| `--accent` | `oklch(82% 0.20 125)` | `oklch(50% 0.18 125)` |
| `--accent-hover` | `oklch(75% 0.22 125)` | `oklch(42% 0.18 125)` |
| `--accent-foreground` | `oklch(15% 0 0)` | `oklch(99% 0 0)` |
| `--accent-soft` | `--accent / 0.18` | `--accent / 0.18` |
| `--accent-tint` | `--accent / 0.10` | `--accent / 0.10` |

Hue 125 sits in the deutan-tolerant slot of the gamut (chartreuse pulled
off pure green) while staying recognisably "Gobby green." Chroma drops
from 0.20 in dark to 0.18 in light because high chroma at lower lightness
reads garish.

**Neutrals tint toward the brand hue at chroma 0.005-0.008.** Surfaces,
text, and borders carry a faint hue-125 cast for subconscious cohesion.
Pure-grey neutrals are not used.

**State palette (locked):**

| Semantic | Hue | Why this hue |
|---|---|---|
| Info | 250 (blue) | Out of the deutan confusion zone; neutral signal |
| Warning | 75 (amber/orange) | Distinct lightness from brand and destructive |
| Destructive / Error | 350 (magenta-pink) | High-saturation pink, not red — survives deutan |
| Success | 125 (lightness-only) | Stays in brand family; differentiated by lightness + icon, never hue alone |

Each state has `_foreground`, `_soft`, `_bg`, `_tint`, and (where needed)
`_text-on-*` siblings. State colors NEVER rely on hue alone — every
state-bearing element must include an icon or position cue, and remain
legible in a desaturated screenshot.

**No agent-specific accent color.** Agents are the core noun of Gobby,
not a state. Agent surfaces draw from the existing semantic palette:
brand accent for active, info for thinking, warning for awaiting
approval, destructive for failed. A dedicated agent hue would dilute the
state palette and flirt with AI-slop purple-on-dark territory. The
legacy `--color-agent` (hue 320) token is to be retired.

**Banned combinations:**

- Red-on-green / green-on-red contrasts of any kind.
- Pure black (`#000`) or pure white (`#fff`) — always tinted neutrals.
- Cyan-on-near-black, purple-to-blue gradients, neon glow accents — the
  2024-2025 AI-dashboard monoculture.
- Gradient text. Solid colors only for text fill.

### Typography

The product-UI typography stack is locked. The marketing site (gobby.ai)
inherits the body and mono pairing but may add a display face for hero
moments — see Surfaces.

**Font stack:**

| Token | Family | Notes |
|---|---|---|
| `--font-sans` | Geist Sans | Body. Self-hosted; matches the Vercel reference without lapsing into Inter/DM Sans monoculture. |
| `--font-mono` | JetBrains Mono | Code, terminal output, copyable values. Already in fallback stack; purpose-built for code. |

No display font in the product UI. At product density, a display face is
decorative — the type scale and weight contrast do the hierarchy work.
The reflex-rejection rules from `impeccable typography` apply to any
future additions: Inter, DM Sans/Serif, Outfit, Plus Jakarta Sans,
Instrument Sans/Serif, IBM Plex *, Space Mono/Grotesk, Fraunces,
Newsreader, Lora, Crimson, Playfair, Cormorant, Syne are all banned.

The current `--font-sans` token in `index.css` still resolves to a
system stack (`-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto`).
Self-hosting Geist Sans is a follow-up — the contract above is the
target, not yet the deployed reality.

**Type scale (fixed rem ladder, base 16px):**

| Token | Multiplier | Computed @ 16px base |
|---|---|---|
| `--text-2xs` | 0.625 | 10px |
| `--text-xs` | 0.6875 | 11px |
| `--text-sm` | 0.75 | 12px |
| `--text-md` | 0.8125 | 13px |
| `--text-base` | 0.875 | 14px |
| `--text-lg` | 1.000 | 16px |
| `--text-xl` | 1.125 | 18px |
| `--text-2xl` | 1.25 | 20px |
| `--text-3xl` | 1.5 | 24px |
| `--text-4xl` | 2.0 | 32px |

The whole ladder rescales when `--font-size-base` is changed via
Settings, so the user controls overall density. Fluid `clamp()` sizing is
reserved for the marketing site, not product UI — no major design system
uses fluid type in product surfaces.

**Weight scale:** 400 / 500 / 600 / 700
(`--font-weight-{normal,medium,semibold,bold}`). Hierarchy comes from
weight + size + spacing, not color.

**Body line-length cap:** `~65-75ch` for any prose surface. Chat
messages, plan documents, and editorial content respect this; dense
tables and feeds are exempt.

### Accessibility Requirements

- **WCAG 2.2 AA** is the floor for all surfaces.
- All state communication must remain legible in monochrome. Test by
  desaturating the screenshot — if you can't tell success from error, the
  design is broken.
- Focus rings are mandatory and must use the brand accent at AA contrast
  against every surface.
- Keyboard parity: every interactive surface reachable and operable without
  pointer.
- Reduced-motion: `prefers-reduced-motion` honored on all animations
  longer than ~150ms. No motion-as-feedback that the user can't disable.
- Touch targets: 44×44 minimum on touch contexts; the UI is desktop-first
  but should not be hostile on a touch screen.

### Design Principles

1. **Status at a glance, depth on demand.** The dashboard must communicate
   system health from across the room. Power users diving in must never hit
   a dumbed-down ceiling. Density grows with attention; decoration does not.

2. **Material precision over decoration.** Hierarchy comes from typography,
   spacing, and depth — not borders, drop shadows, or color stripes.
   Vercel-grade restraint. If a visual element doesn't earn its pixels, cut
   it.

3. **Color is the fourth signal, not the first.** Lightness, icon, and
   position carry meaning. Hue reinforces. Every state communication must
   survive a grayscale screenshot test.

4. **Built for the hands of someone who lives in their terminal.**
   Keyboard-first, command-palette-aware, copyable values, monospace where
   it's load-bearing. Never noisy, never patronising, never animated for
   show.

5. **Equal polish in dark and light.** Light mode is not the discount
   theme. Component stories, screenshots, and visual review run in both.

6. **One system, two postures.** The product UI evolves in place toward
   this contract; the gobby.ai marketing site is the greenfield surface
   built fresh against it. Both inherit the same tokens, voice, and
   constraints — they diverge only on density, motion budget, and
   editorial weight.
